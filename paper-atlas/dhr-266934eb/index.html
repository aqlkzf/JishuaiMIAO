DHR：把蛋白同源搜索改写成向量检索

问题：远缘同源既难找，又搜索得慢

传统蛋白同源搜索通常依赖局部序列比对、profile HMM 或结构比对。序列相似度很低的远缘同源可能保留折叠与功能，却缺少显著局部匹配；HMMER 一类 profile 方法更敏感，但在数千万到数亿条数据库上建立 MSA 很耗时。DHR（Dense Homolog Retriever）的核心做法是：先用蛋白语言模型把数据库序列离线编码成固定长度向量，在线时只编码 query，再用 FAISS 做近邻搜索，把大数据库缩成 top-$K$ 候选；需要 MSA 时，再让 JackHMMER 只处理这个候选子集。

DHR 并不直接产生最终比对。它是高召回的候选检索器；“DHR + JackHMMER”才是论文用于 MSA/AlphaFold2 下游的完整链。

为什么使用两个编码器

query 与数据库候选的角色不对称：query 要在一个共同索引中找到候选，database embedding 则必须预先缓存。DHR 用两个参数独立的 Transformer 编码器：

\[h_q=f_{\Theta}(q),\qquad z_c=f_{\Psi}(c),\]

再以点积

\[s(q,c)=h_q^\top z_c\]

作为论文定义的相似度。同一条蛋白作为 query 或 candidate 时可以得到不同表示，这给模型学习非对称检索角色的自由度。

论文主实验以 ESM-1b 初始化两个编码器，取首个 token 的 768 维表示作为整条序列向量。本地当前主分支代码则默认加载两个 esm2_t12_35M_UR50D，取最后一层 CLS token，默认是 480 维。这不是文字差异：论文报告在验证子集上 ESM-1 与 ESM-2 recall 分别为 0.87 和 0.86，因而正文采用 ESM-1；仓库 README 说明主分支是面向大规模搜索的 v2，如需 ESM-1/预建索引应切 v1。

正样本怎样构造

论文从约 200 万条 UR90 query 出发，用 HHblits/UniClust30 构建 MSA，并把同一个 MSA 中的 query 与随机 homolog 组成正对 $(q_i,c_i)$。每个 MSA 截到 1,000 条候选。这个监督信号实质上让 DHR 学习模拟传统同源搜索产生的邻域，因此它不是完全无监督地发现同源关系；它把已有 MSA/profile 工具的知识蒸馏进快速向量检索器。

论文也承认，仅模仿 JackHMMER 可能限制新生物关系的发现。不过蛋白语言模型预训练已经编码了序列统计、结构和共进化信号，因此 DHR 可在训练教师难以检出的远缘案例中产生不同排序。

对比损失怎样工作

一个 batch 含 $b$ 个正对。编码后构造相似矩阵

\[S_{ij}=h_i^\top z_j.\]

对第 $i$ 个 query，$c_i$ 是正例，其余 batch 内候选充当负例：

\[L_i=-\log\frac{\exp(S_{ii})}{\sum_{j=1}^{b}\exp(S_{ij})}, \qquad L=\frac{1}{b}\sum_i L_i.\]

本地 biencoder.py 直接用矩阵乘法、log_softmax 和 nll_loss 实现这一式；分布式时 SyncFunction 汇集各 GPU embedding，扩大 in-batch negative 集。论文写每张 V100 放 136 对，并用 cross-batch negatives 把有效 batch 扩到 544，训练十个 epoch。

但当前代码有一个论文未强调的实现边界：forward() 对 query 分支包裹 torch.no_grad()，所以训练时 query encoder 被冻结，梯度只更新 candidate encoder。论文公式把 $\Theta$、$\Psi$ 都称为可学习参数；因此“两个编码器联合微调”不能从这份主分支源码得到支持。本地代码能确认的是当前快照的单侧更新行为。

从数据库到 top-$K$ 候选

推断分三步：

  1. do_embedding.py 用 candidate encoder 批量编码 TSV 数据库，并把每批 embedding 写成 .pt。
  2. do_agg.py 聚合向量，建立 480 维 FAISS 索引，同时保存序列 ID/内容表。
  3. do_retrieval.py 用 query encoder 编码输入，在索引中搜索 top-$K$，把每个 query 的候选输出为 TSV。

离线编码成本高，但数据库不变时只做一次；在线成本主要是一次 query 编码和向量搜索。论文称 7,000 万条 UniRef90 可在单 GPU 上数秒检索，速度随数据库规模近似线性。

这里存在一个重要的论文—代码不一致。论文和训练代码使用点积；释放的 do_agg.py 却创建 faiss.IndexFlatL2(480)。默认 proj_dim=0 时 embedding 没有执行 $L_2$ 归一化，代码中归一化行是注释状态。只有向量范数相同或已归一化时，最大点积与最小欧氏距离才给出相同排序：

\[\lVert h-z\rVert_2^2=\lVert h\rVert_2^2+\lVert z\rVert_2^2-2h^\top z.\]

因此当前主分支的 FAISS 排名未必严格实现论文的点积检索。复现实验应明确选择 IndexFlatIP，或显式归一化 query/database 后再用 L2，并验证与论文 checkpoint 的预期一致。

JackHMMER 与 MSA 是另一段流水线

论文把 top-$K$ 候选交给 JackHMMER，使用接近 AF2 默认参数进行一轮或多轮搜索。$K$ 越大，候选覆盖通常越高，但 JackHMMER 部分更慢。论文在 CASP13/14 展示：top-$K$ 增大时与 AF2 默认 MSA 的重叠接近 90%；无 contrastive training 的 ESM embedding 仅约 35%，说明收益不只是预训练表示本身。

MSA 多样性用 Meff 衡量：相似序列被降权，冗余的很多条序列不应等价于很多独立进化信息。论文进一步比较 DHR MSA、AF2 默认 MSA 和合并后的 DHR-meta；合并常能补充不同同源集合，在 CASP13/14 结构预测中带来收益。

当前 do_retrieval.py 实际只写出 top-$K$ TSV。my_align() 未被调用，且其中 qjackhmmer 命令模板不完整；README 命令也依赖脚本内硬编码的 checkpoint 路径。因而仓库主分支可运行的核心是 embedding/index/retrieval，不能宣称它一条命令完整复现论文 MSA 与 AF2 结果。JackHMMER、ColabFold/AF2、数据库与模型权重需要另外准备和衔接。

结果怎样读才准确

在 SCOPe family top-200 比较中，论文报告 DHR sensitivity 约 93%，HMMER 约 91%；DHR 在 MMseqs2 难例和 superfamily 层级尤其有优势。AUC-1FP 只累计到第一个 false positive 之前，强调排名前端的纯度；它与全排序 recall 是不同问题。

图 2 的 c.55.3.5 案例显示，DHR 高排名序列在结构上与 query 更相似，而序列比对方法失败；另有候选后来被 SCOP2 放入相同家族，说明 embedding 可为数据库校订提供线索。但这些是案例证据，不能说明所有高点积候选都是新同源。

图 3–5 评估 MSA 速度、覆盖、Meff 与 AF2 结构质量。速度倍数依赖数据库、硬件、$K$、JackHMMER iteration 和是否计入离线索引成本；“28,700 倍”主要比较纯在线 homolog detection 与 profile 方法，“93 倍”对应特定 DHR+JackHMMER MSA 设置，不能互换。

图 6 扩展到 CASP15、BFD/MGnify 和 New-Protein。DHR 与 ColabFold/MMseqs2 的 MSA 有大量重叠但不完全相同；合并 MSA 的 Meff 更高。结构结果支持 DHR 作为补充检索通道，而不是证明 embedding 检索普遍替代所有 profile/structure 搜索。

长序列、域结构与误判边界

论文指出超过约 1,000 个残基的序列检索质量下降。一个 CLS 向量压缩整条多域蛋白，可能混合不同域信号；代码还在训练时把 query 截到 400 aa、candidate 截到 800 aa，推断 SingleConverter 截到 800 aa。论文文字使用 “nt” 的若干图轴/段落与蛋白 amino-acid 语境不一致，解读时应按蛋白序列长度，而非核苷酸模型。

in-batch negative 也可能包含未标注同源，即把 false negative 推远。SCOPe 标签并非完美，family/superfamily 层级结论依赖数据库版本；结构相似也不总等价于共同进化来源或相同功能。

复现合同

论文列出的关键版本包括 Python 3.8.12、PyTorch 1.11.0、NumPy 1.21.2、pandas 1.3.1、fair-esm 1.0.0、FAISS 1.7.2、ColabFold 1.3.0 和 MMseqs2 13.45111。本地 environment.yml 大体锁定旧 CUDA/PyTorch/FAISS 生态，重建环境可能受当前 channel 包可用性影响。

本地代码快照记录为提交短号 4305a60，但嵌套 .git 元数据已移除，无法在当前工作区独立恢复完整 upstream commit；目录又处于 PaperCode 外层仓库，因此外层 git rev-parse 不是 DHR 上游提交。模型 checkpoint 在 Google Drive，数据库规模巨大，完整训练/索引/AF2 基准均未包含。

本地补充材料已核对。MOESM1 是 69 页的附加结果，包含 SCOPe 时间与难例、CASP13–15 明细、CATH 多域评测、HHblits 比较、CAID 无序蛋白、并行 DHR-AF2 和 FAISS 内存表。它补充了边界而不是消除边界：例如 HHblits 在 AUC-1FP 上略优，而 DHR 在 sensitivity/速度上更强；补充也明确 DHR-AF2 吞吐受 JackHMMER 和未充分工程整合限制。MOESM2 是三页 reporting summary，记录软件版本、公开数据来源、约 200 万训练 query、随机 train/test split 和无 blinding；它不是额外方法代码。

一句话总结

DHR 的真正创新是把昂贵的全库同源搜索拆成“语言模型双编码器 + 对比学习 + 离线向量索引 + 小候选集 profile 精炼”。论文证明它在多个 benchmark 上很有竞争力；释放代码则同时暴露了需要复现者主动处理的分支版本、距离度量、冻结策略、长度截断和 JackHMMER 衔接差异。

DHR Summary

Motivation & Novelty

Biological problem: Identifying evolutionarily related proteins (homologs) is foundational to bioinformatics — essential for function annotation, evolutionary analysis, MSA construction for structure prediction, and drug discovery. Alignment-based methods fail in the “twilight zone” (<20-30% sequence identity) where homologs are remote but structurally and functionally related.

Limitations of existing approaches:

  • PSI-BLAST (Nucleic Acids Res., 1997): k-mer seeding misses remote homologs with low sequence similarity; no structural information; quadratic complexity for all-vs-all
  • MMseqs2 (Nature Biotechnology, 2017): fast and sensitive but still alignment-based; profile-based iteration requires prior MSA; >56% below DHR at superfamily level
  • HMMER (PLoS Comput. Biol., 2011): best profile-based sensitivity but extremely slow (28,700× slower than DHR); requires existing MSA to build initial profile
  • DIAMOND (Nature Methods, 2015): fast but trades sensitivity for speed
  • Foldseek (Nature Biotechnology, 2024): requires predicted/experimental structures; comparable to sequence methods at family level, much slower
  • ESMFold/OmegaFold (Science, 2023; Nature Biotechnology, 2022): bypass MSA but ~2 Å worse r.m.s.d. than MSA-guided AF2 on CASP14, and prohibitively memory-hungry for long sequences (>650 aa)

Unique contributions:

  1. Dense retrieval for protein homology: applies bi-encoder dense retrieval (from NLP) to proteins for the first time; alignment-free by design
  2. ESM-based embeddings with contrastive learning: captures implicit structural and coevolutionary information within sequence-only embeddings through contrastive training on JackHMMER-derived MSAs
  3. Demonstrated downstream utility: shows that DHR-constructed MSAs improve AF2 structure prediction by 0.4 Å r.m.s.d. on CASP14 and match ColabFold-MMseqs2 on CASP15 despite training on a 100× smaller database
  4. Scale and speed: 22× faster than BLAST, 28,700× faster than HMMER; retrieves from 70M-sequence UniRef90 in seconds on a single GPU

Method Overview

Core framework: DHR = Dual Encoder + Contrastive Learning + FAISS Retrieval

  1. Pretraining base: Both query encoder ($f_\Theta$) and candidate encoder ($f_\Psi$) are initialized from ESM protein language model (ESM-2 t12_35M in released code; ESM-1b in the paper). ESM is pre-trained on 250M protein sequences, capturing protein secondary structure, contacts, and evolutionary information in its representations.

  2. Contrastive fine-tuning: Positive pairs $(q, c)$ are drawn from JackHMMER-constructed MSAs on UniClust30. In-batch negatives (cross-GPU via all_gather) train the model to maximize dot product similarity for homologous pairs and minimize it for non-homologous ones. Loss: $L = -\frac{1}{b}\sum_i \log(e^{s_{ii}} / \sum_j e^{s_{ij}})$.

  3. Offline database embedding: The candidate encoder embeds all of UniRef90 (70M sequences) into 480-dim vectors once, stored in a FAISS flat index.

  4. Online retrieval: A query is embedded by the query encoder; FAISS returns top-K (default 400k) nearest sequences in ~1 second.

  5. MSA construction: Top-K sequences are fed to JackHMMER (same parameters as AF2 default), which builds the final MSA in minutes rather than hours. DHR acts as a prefilter, replacing the full 70M sequence scan with a 400k targeted scan.

Evaluation

Datasets

  • SCOPe 2.08 (5,065 family queries, 2,065 superfamily queries): gold-standard structural hierarchy for homolog detection benchmarks
  • CASP13DM (n=106 domain sequences): MSA quality and AF2 structure prediction
  • CASP14DM (n=92): comparison to MSA-free methods (ESMFold, OmegaFold)
  • CASP15 (n=50): scalability to BFD/MGnify (300M sequences)
  • New-Protein (n=650, PDB cutoff Jan 2022-2023): held-out recent structures

Ablation

  • “DHR-w/o con” (no contrastive training, raw ESM embeddings): MSA overlap with JackHMMER drops from ~90% to ~35%; confirms contrastive training is essential
  • ESM-1 vs ESM-2 selection: recall 0.87 vs 0.86 (marginal); both shipped

Reproducibility

Rating: 3 / 5

Justification: The inference pipeline (embed → retrieve → JackHMMER) is reproducible with the provided checkpoints and scripts. However, training scripts are not released, the JackHMMER integration is a dead code stub requiring manual setup, and there are implementation discrepancies (ESM-2 vs ESM-1b, FAISS L2 vs dot product).

Strengths:

  • Pre-trained checkpoint available (Google Drive)
  • Three-step pipeline (do_embedding → do_agg → do_retrieval) is clear
  • Standard tools (FAISS, JackHMMER, ColabFold) are well-documented
  • Environment fully specified in environment.yml
  • Open-source under permissive license

Weaknesses:

  • No training script released; cannot reproduce model from scratch
  • JackHMMER integration is incomplete in the released code (my_align is never called)
  • FAISS L2 ≠ training dot product metric for unnormalized embeddings
  • SCOPe benchmark scripts not in main branch (mentioned as v1 branch)
  • Requires ~134 GB RAM for full UniRef90 embedding storage
  • PyTorch 1.11 / CUDA 11.3 environment may conflict with modern systems

Common pitfalls:

  • PhyloPandas dependency was removed in August 2024; use TSV format only (not FASTA)
  • Checkpoint path must be absolute in Hydra config
  • Multi-GPU embedding requires MASTER_PORT to be set in config
  • CASP benchmarks are on v1 branch, not main

Data availability: All data from public sources (UniRef90, CASP, PDB, SCOPe, BFD/MGnify). Download scripts not provided but standard.

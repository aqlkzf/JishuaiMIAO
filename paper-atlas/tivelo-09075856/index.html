TIVelo: RNA velocity estimation leveraging cluster-level trajectory inference

Open paper

TIVelo 方法解读：先确定发育方向，再让速度指向“未来邻居”

一句话理解

许多 RNA velocity 方法先逐基因拟合剪接动力学，再把速度汇总成细胞流场；若一批基因的相图被反向拟合，汇总方向也会错。TIVelo 反过来做：先从簇图提出一条候选发育路径，用 unspliced RNA 领先 spliced RNA 的相位规律判断路径朝向；确定簇级父子方向后，再要求每个细胞的速度指向同簇或子簇中伪时间更晚的邻居。

它利用聚类、PAGA 和 diffusion pseudotime 作为结构先验。因此输出方向并非完全“无监督从剪接计数读出”，而是剪接相位证据与预先构造的簇拓扑共同决定。

输入与输出

输入 AnnData 至少需要：细胞簇标签、低维嵌入、邻居图，以及 scVelo 预处理产生的 Mu/Ms（邻域平滑后的 unspliced/spliced 矩）。顶层 tivelo() 并不自动从原始 counts 生成 Mu/Ms。

主要输出包括：校正后的起始簇和主路径、簇的有向子节点字典、directed nearest-neighbor graph（dNN）、每个细胞的 spliced/unspliced velocity，以及交给 scVelo 构造的 velocity graph 与嵌入流线。

第一步：从无向簇图提出候选主路径

TIVelo 先运行 PAGA 得到簇间连通图，结合 root/end stationary-state score 选择候选起点，再剪枝并寻找覆盖较多细胞的主路径。主路径此时只有“从候选起点出发”的方向，可能整体反了；它的作用是把复杂数据压成一条适合检验相位先后的细胞序列。

沿该路径以候选根运行 diffusion pseudotime（DPT），把每个基因的 $u$ 和 $s$ 排成时间序列。DPT 本身依赖邻居图和根细胞，因此它是排序坐标，不是真实采样时间。

第二步：用 orientation score 校正方向

1. 相位规律

正确的时间方向下，基因上调时 $u$ 先升、相对上常有 $u>s$；下调时 $u$ 先降、相对上常有 $u<s$。若把时间倒放，这两个规律会系统性反转。

为避免 $s$ 的绝对量通常远大于 $u$，TIVelo 对每个基因分别归一化：

\[\tilde u_{n,g}\leftarrow\frac{\tilde u_{n,g}}{\sum_n\tilde u_{n,g}}, \qquad \tilde s_{n,g}\leftarrow\frac{\tilde s_{n,g}}{\sum_n\tilde s_{n,g}}.\]

源码先以长度 100 的均值卷积平滑两个序列，再分别拟合 piecewise-linear model tree。树的每个叶保存局部直线斜率，从而标出 $u,s$ 同时上升或同时下降的连续区段。

2. 分数如何计算

令 $d_{n,g}=\tilde u_{n,g}-\tilde s_{n,g}$，对同升区段取正号，对同降区段取负号，并用连续区段长度 $l_\tau$ 加权：

\[S_g= \sum_{n\in\mathrm{rise}}l_{\tau(n)}d_{n,g} -\sum_{n\in\mathrm{fall}}l_{\tau(n)}d_{n,g}.\]

例如某上升段有 3 个细胞，$d=(0.02,0.03,0.01)$，该段贡献为 $3\times0.06=0.18$；若同样的差值出现在下降段，则贡献为 $-0.18$。长而一致的相位段因此比零碎波动更有影响。

TIVelo 只聚合通过 compute_velocity_genes() 质量过滤的基因。默认以均值汇总 $\bar S$：若 $\bar S<0$，反转主路径并把另一端设为起点；随后还逐支路评分，必要时反转和拼接支路，得到最终根与路径。

3. 论文与实现的一个重要差异

论文描述的线性树停止条件与发布代码并不完全相同。当前 orient_score() 默认 rate=1e-10, dur=100, kernel_size=100：每个子段至少 100 个细胞，只要有效切分仍实质改善平方误差就继续。不能把论文文字中的阈值直接当作当前包的运行参数。

方向分数也不是适用于所有基因的物理定律：极弱信号、复杂多相转录、错误聚类或错误主路径都可能改变分数。它提供的是群体级相位支持，不是单基因因果检验。

第三步：把簇方向变成 directed nearest neighbors

校正根后，TIVelo 在完整 PAGA 图上从根向外分层，依据连通权重建立每个簇的子簇集合。再从根细胞重算 DPT。细胞 $n’$ 只有同时满足以下条件才是细胞 $n$ 的 dNN：

  1. $n’$ 在 $n$ 的普通 kNN 中；
  2. $t’n\le t’{n’}$，即伪时间不早于 $n$；
  3. $n’$ 与 $n$ 同簇，或位于 $n$ 所在簇的直接子簇。

源码对应矩阵操作是

\[D=K\odot(C_{child}+C_{same})\odot I(t'_n\le t'_{n'}).\]

注意代码使用 <= 而非论文叙述中更严格的 <。一般连续伪时间下差别小，但出现并列值时会额外保留同时间邻居。

第四步：让速度指向未来邻域

对表达向量 $x_n$，dNN 的均值记为 $\bar x_{dnn(n)}$。无约束闭式速度就是

\[\tilde v_n=\bar x_{dnn(n)}-x_n.\]

这很好理解：当前表达加上速度后，应落到局部未来状态。若一个基因当前 spliced expression 为 2，而未来邻居均值为 2.7，则该基因速度为 $+0.7$；若未来均值为 1.4，则为 $-0.6$。

发布代码把 v_u、v_s 初始化成上述差值，再用 Adam 优化。MSE 模式的完整损失可概括为

\[L=L_u+\lambda L_s-\lambda' C_u-\lambda' C_s,\]

其中 $L_u,L_s$ 使 $u+v_u$、$s+v_s$ 接近 dNN 均值；$C$ 奖励相邻同簇细胞的速度余弦一致，默认 $\lambda=1,\lambda’=0.1$。

不过顶层 tivelo() 默认 only_s=True，实际默认损失是 $L_s-\lambda’C_s$，只更新并用于 downstream 的 spliced velocity。only_s=False 才同时拟合两层。这个默认行为比只读论文总公式更重要。

随后代码调用 scvelo.tl.velocity_graph() 与 velocity_embedding()，利用速度和邻居状态差的余弦相似度建立转移图并投影到 UMAP。嵌入流线是高维速度经过邻域与二维投影后的可视化，不等同于直接在 UMAP 坐标上训练的真实动力学。

可选 kinetic-rate mode

可选模式用神经网络从每个细胞的 $u,s$ 预测 cell-specific $\alpha,\beta,\gamma$，再按

\[v_u=\alpha-\beta u,\qquad v_s=\beta u-\gamma s\]

计算速度，并仍受 dNN 目标监督。论文报告的网络为 $2G\to256\to64\to3G$、训练 300 epochs；发布 wrapper 默认隐藏层为 [128,64]、顶层默认 n_epochs=100。若要复现论文 kinetic 设置必须显式传参，不能依赖默认值。

实际使用的边界检查

应对聚类分辨率、候选根、PAGA 阈值、DPT root cell、orientation 的窗口/最小段长、dNN 邻居数和 coherence 权重做敏感性分析。尤其要比较 only_s=True/False、约束与简单闭式解、默认与 kinetic mode。若不同合理聚类会翻转方向，或数据含汇合、循环、跨簇跳跃和多条同等主路径，则“树状簇拓扑 + 单根 DPT + 直接子簇未来邻居”的假设需要明确报告，而不能只展示一张平滑流线图。

TIVelo: RNA Velocity Estimation via Cluster-Level Trajectory Inference

Paper: “TIVelo: RNA velocity estimation leveraging cluster-level trajectory inference” Authors: Muyang Ge, Jishuai Miao, Ji Qi, Xiaocheng Zhou, Zhixiang Lin Journal: Nature Communications 16, 2025 DOI: 10.1038/s41467-025-61628-x Code: https://github.com/cuhklinlab/TIVelo

Motivation & Novelty

Biological Problem

RNA velocity infers the direction and speed of cell developmental processes from a single-cell RNA-seq snapshot, by comparing unspliced (u) and spliced (s) RNA counts. Since u is a precursor of s, the u-s relationship encodes the direction of transcriptional change: during induction, u rises before s; during repression, u falls before s.

Limitations of Existing Methods

Many major RNA velocity methods — velocyto (Nature 2018), scVelo (Nature Biotechnology 2020), UniTVelo (Nature Communications 2022), VeloVI (Nature Methods 2024), DeepVelo (Genome Biology 2024), cellDancer (Nature Biotechnology 2024), and latent/Neural-ODE methods such as scTour and LatentVelo — depend on explicit kinetic modeling or fit velocities gene-by-gene before aggregation: \(\frac{du}{dt} = \alpha - \beta u, \quad \frac{ds}{dt} = \beta u - \gamma s\) with constant kinetic parameters. This fails when:

  1. MURK genes (Multiple Rate Kinetics) have non-constant transcription rate $\alpha$ — the ODE fit may actually point in the wrong direction
  2. Gene aggregation: velocities from different genes can be contradictory (some say “going forward”, others say “going backward”), and their aggregate is confused
  3. Limited direction recovery: if the inferred root or gene-level signs are inconsistent, the final stream can point opposite to the expected lineage

What TIVelo Does Differently

TIVelo introduces a two-stage approach:

  1. Cluster-level direction inference using an orientation score — a model-free statistic that asks “does u lead s in this pseudotime ordering?” without fitting any ODE
  2. Supervised velocity estimation where each cell’s velocity is constrained to point toward its directed nearest neighbors (cells in the same or child clusters, at later pseudotime)

Key distinctions:

  • No ODE assumption in the direction inference step: the score only asks whether u leads s along a pseudotime ordering.
  • Automatic direction correction: if the aggregated orientation score is negative, the origin node/path is reset.
  • Cluster-level topology first, cell-level velocity second: PAGA/path orientation constrains each cell’s velocity toward directed nearest neighbors, reducing the effect of individual gene misfits.

Method Overview

TIVelo has three main steps. Full mathematical derivation and code mapping in doc_method.md.

Step 1: Main Path Selection

Build a PAGA cluster graph, prune small/isolated clusters, select an origin node (cluster with high root score, low end score), and greedily select the main developmental path that covers the most cells.

Step 2: Orientation Inference (Core Innovation)

For each gene $g$ along the main path:

  1. Order cells by diffusion pseudotime → time series $\tilde{u}_g(t)$, $\tilde{s}_g(t)$
  2. Normalize both to sum=1 (enables comparison across expression levels)
  3. Smooth with 1D convolution (kernel_size=100)
  4. Fit a linear regression tree (piecewise linear, numba-JIT) to detect rising/falling phases
  5. Compute orientation score $S_g$: in rising sections, if $u > s$ (u rose first), contributes positively; in falling sections, if $u < s$ (u fell first), contributes positively

Aggregate: if $\bar{S} = \frac{1}{G}\sum_g S_g < 0$ → the pseudotime direction is wrong → flip the origin node.

This approach is robust to MURK genes and complex expression patterns because it operates on local pseudotime sections rather than fitting a single global kinetic curve.

Step 3: RNA Velocity Estimation

After establishing the correct direction, build a directed nearest neighbor graph (dNN): for each cell $n$, its dNN contains k-nearest neighbors that are in the same or a child cluster AND at later pseudotime. Velocity is estimated so each cell’s expression + velocity equals the mean expression of its dNN: \(\tilde{v}_{n,g}^{(s)} = \frac{1}{N_n}\sum_{n' \in dnn(n)} s_{n',g} - s_{n,g}\)

Optionally, an Adam optimizer refines velocities with a coherence regularization term ($\lambda’=0.1$) to encourage nearby cells in the same cluster to have consistent velocities. In the released package, the default top-level call uses the spliced velocity layer for downstream scVelo graph construction.

Kinetic rate mode (optional): the paper describes a 3-layer DNN $[2G \to 256 \to 64 \to 3G]$ that infers per-cell kinetic rates $(\alpha, \beta, \gamma)$, then derives velocities from ODE equations. The released wrapper defaults to $[2G \to 128 \to 64 \to 3G]$, so paper-style kinetic settings should be passed explicitly.

Evaluation

Datasets

  • 16 real datasets including: mouse gastrulation (erythroid), dentate gyrus, intestinal organoid, mouse retina, mouse hindbrain, RPE1-FUCCI, U2OS-FUCCI, HSPCs, embryonic mouse brain, SHARE-seq mouse skin, developing human brain
  • Cell-cycle validation (FUCCI): RPE1 (290 positions) and U2OS (996 positions) — ground truth provided by fluorescent cell-cycle indicator

Metrics

  • CBDir (Gene space): cross-boundary direction correctness in high-dimensional gene space (new metric proposed by TIVelo)
  • CBDir (UMAP space): original CBDir metric from VeloAE (Nature Computational Science 2022)
  • TransCosine: velocity graph consistency with expected cluster transitions
  • VeloCoh: coherence between velocity and transition-predicted future state (from VeloVI)
  • Sign accuracy: fraction of velocity components matching the sign of empirical velocity from cell-cycle position differences

Results

Key biological findings:

  • Correctly resolves MURK gene direction in mouse gastrulation (erythroid)
  • Correctly identifies bifurcation in dentate gyrus (nIPC → Granule vs nIPC → Astrocytes)
  • Recovers reversed orientation in intestinal organoid (negative $\bar{S} = -0.650$) automatically
  • Outperforms MultiVelo on RNA velocity despite using only RNA (no ATAC data)

Reproducibility

Rating: 4/5

Strengths:

  • Clean Python package with clear entry point: tivelo.tivelo(adata, group_key, emb_key)
  • GitHub repo (https://github.com/cuhklinlab/TIVelo) with tutorial notebooks and test datasets
  • All 16 datasets are publicly available (cited in paper)
  • Strict dependency pinning: scvelo==0.3.1 prevents compatibility issues
  • Numba JIT compilation speeds up the main bottleneck (linear tree fitting)

Weaknesses / Practical Notes:

  • scvelo==0.3.1 is a strict requirement — newer scvelo versions may break the API
  • Package entry point expects Mu/Ms moments to exist; preprocessing is not fully encapsulated in tivelo.tivelo()
  • Sign accuracy (FUCCI evaluation) is not in the released package utilities — it appears to be computed in external benchmark scripts/notebooks
  • The paper mentions 300 epochs and hidden dimensions 256/64 for kinetic mode, while the library default is n_epochs=100 and wrapper default hidden dimensions are 128/64
  • Large datasets with complex topologies may require manual tuning of clustering resolution (use lower res for simpler cluster graph)
  • No GPU support for the default (non-kinetic) velocity fitting mode; kinetic DNN is GPU-compatible via PyTorch

Environment setup:

pip install tivelo
# Or from source:
git clone https://github.com/cuhklinlab/TIVelo && cd TIVelo && pip install -e .
# Requires scvelo==0.3.1 (strict)

Common pitfalls:

  1. Providing group_key that doesn’t match adata.obs column name → silent error
  2. Very small datasets (<200 cells per cluster) may not have enough cells for linear tree convergence
  3. Complex branching topologies may need res reduction before running TIVelo
  4. rate_mode=True requires GPU for reasonable speed on large datasets

TOGL：把图的连通分量与环写回 GNN 表示

TOGL（Topological Graph Layer）解决的是消息传递 GNN 的一个结构盲区：局部邻居聚合的表达能力不超过 WL[1]，因此可能无法区分局部度数完全相同、但全局连通性或环结构不同的图。论文的关键设计不是在分类器末端附加一个固定拓扑描述符，而是把可学习的持久同调计算做成一个可插入 GCN、GIN 或 GAT 中间的层，让后续消息传递继续使用拓扑增强后的节点表示。

一句话数据流

\[\{x^{(v)}\}_{v\in V} \xrightarrow{\Phi}\{f_i(v)\}_{i=1}^k \xrightarrow{\mathrm{PH}}\{\mathcal D_i^{(0)},\mathcal D_i^{(1)}\}_{i=1}^k \xrightarrow{\Psi} \bigl(\widetilde x^{(v)},h_G^{(1)}\bigr).\]

其中，$x^{(v)}$ 可以是原始节点属性，也可以是前面 GNN 层产生的隐藏表示；$\widetilde x^{(v)}$ 继续送入后续 GNN；$h_G^{(1)}$ 是周期信息的图级表示，默认在分类前拼接。

1. 学习多个“观察图的顺序”

单个 Betti 数 $\beta_0$（连通分量数）或 $\beta_1$（独立环数）过于粗糙。TOGL 用一个单隐层 MLP

\[\Phi:\mathbb R^d\to\mathbb R^k, \qquad f_i=\pi_i\circ\Phi\]

为每个节点生成 $k$ 个标量。对第 $i$ 个过滤，节点按 $f_i(v)$ 从小到大进入子图；边 $(u,v)$ 的进入时间是

\[f_i(u,v)=\max\{f_i(u),f_i(v)\},\]

即两个端点都出现后边才出现。不同的 $f_i$ 相当于从不同任务相关角度扫描同一张图。代码中的共享版本是 models.py:71-78，一次输出全部 $k$ 个值；独立版本是 models.py:79-87。边过滤值的 max 实现在 models.py:115-116。

2. 从过滤序列得到拓扑事件

对每个过滤，持久同调返回两个图：

  • $\mathcal D_i^{(0)}$ 记录连通分量的出生与合并。它恰有 $ V $ 个条目，并能与产生分量的节点一一对应。
  • $\mathcal D_i^{(1)}$ 记录环的产生。条目与产生环的边对应；没有产生环的边在实现中使用 $(0,0)$ 哑元。

因此一个点 $(b,d)$ 的含义不是一个普通二维坐标，而是某个拓扑特征在过滤值 $b$ 出现、在 $d$ 消失；$d-b$ 越大，特征跨越的过滤尺度越长。

本地实现先删除 PyG 无向图的反向重复边（data_utils.py:66-87），再把节点值、边值和边索引转到 CPU，调用外部 compute_persistence_homology_batched_mt，最后把结果传回原设备（models.py:104-141；DeepSets 版本对应 layers.py:295-323）。这说明论文给出的 $\mathcal O(m\log m)$ 算法复杂度之外，实际训练还承担 CPU/GPU 往返成本。

3. 把持久图变成神经网络特征

论文把持久图嵌入记为 $\Psi$。代码提供两条路径：

  1. TopologyLayer 使用 Triangle、Gaussian、Line、RationalHat 四类可学习坐标函数（coord_transforms.py:7-126）。它们逐点处理 $(b,d)$，再把不同过滤、不同函数的输出拼接。
  2. SimpleSetTopoLayer 使用 DeepSets（layers.py:226-378）。与逐点坐标函数不同，它通过集合聚合让一个持久点的表示感知同一图中的其他持久点。

论文报告这些嵌入函数没有始终占优者，因此把选择留作超参数；这不是“DeepSets 必然更好”的结论。

4. 为什么 0 维和 1 维走不同出口

0 维条目与节点一一对应，所以 TOGL 可以把其嵌入直接写回节点：

\[\widetilde x^{(v)}=x^{(v)}+ \Psi^{(0)}(\mathcal D_1^{(0)},\ldots,\mathcal D_k^{(0)})[v].\]

坐标函数版本在 models.py:188-223 完成投影、归一化和残差；DeepSets 版本在 layers.py:326-378 完成同类更新。两者的激活与 BN 顺序并不完全相同，不能把它们描述为逐行相同的实现。

1 维条目对应边而非节点。论文因此将有效周期条目池化为图级向量，并在最终分类头前拼接。代码在 models.py:168-186 按图求和，在 models.py:598-629 把 TOGL 插入指定位置并处理最终拼接。额外的 dist_dim1 选项可把图级周期向量广播回节点；这是代码扩展，不是论文主叙述的默认数据流。

5. 端到端训练为何可行

持久配对本身会随排序发生离散改变，但论文定理 1 给出的条件是：若某组参数下节点过滤值互不相同，且 $\Psi$ 可微，那么

\[\theta\mapsto\Psi\bigl(\mathbf{ph}(G,f_\theta)\bigr)\]

在该参数点可微。这里应理解为满足过滤值互异条件时的局部可微性，而不是对所有参数全局光滑。实现将 PH 返回的配对继续交给 PyTorch 运算，使分类损失能够训练过滤 MLP 和嵌入参数。

6. 表达能力结论及边界

论文定理 2证明：若 WL[1] 能区分两个图，就存在一个单射过滤使它们的 0 维持久图不同；再结合“两个互不相交三角形”和“一个六边形”的反例，持久同调还能区分 WL[1] 无法区分的图。前者有 $(\beta_0,\beta_1)=(2,2)$，后者为 $(1,1)$。

这证明的是函数类的表达能力，不保证优化一定学到证明中构造的过滤，也不保证每个数据集都提升。论文自己报告 GIN/PROTEINS 与 GAT/PATTERN 等反例，并指出过滤质量依赖骨干 GNN。

7. 如何读主要图和实验

  • 图 1 的 CYCLES 可由静态 Betti 信息区分；NECKLACES 两类具有相同环数，需要学习任务相关过滤。图中 GCN-TOGL 以更少层数接近满分，而静态 PH 在 NECKLACES 上接近机会水平。
  • 图 2 从左到右画出完整机制：节点属性、$\Phi$ 输出的 $k$ 个值、$k$ 个图视角、过滤、持久图嵌入、与原节点表示融合、输出拓扑增强节点表示。
  • 图 3 显示结构版 MNIST 上 TOGL 在浅层网络中更快取得较高精度，但它支持的是“减少达到高性能所需深度”，不是普遍消除过平滑。
  • 表 1 的结构实验中，GCN-4 到 GCN-3-TOGL-1 在 DD、MNIST、PROTEINS 上分别由 $68.0\pm3.6$、$76.2\pm0.5$、$68.8\pm2.8$ 提升到 $75.1\pm2.1$、$84.8\pm0.4$、$73.8\pm4.3$。
  • 补充表 S12 的球面/环面任务中，GCN 版本由 $77.8\pm2.1$ 提升到 $98.5\pm1.3$，GIN 版本由 $76.2\pm3.5$ 提升到 $99.6\pm0.9$。这是几何拓扑信号突出的合成案例，不能直接外推到所有真实图数据。

8. 复现与实现边界

  • 本地代码快照来自 https://github.com/BorgwardtLab/TOGL，提交 d0c986cf829ca6bbae1a23e5cdab1c99146503cd。
  • 默认 CLI 为 8 个过滤、每类 3 个坐标函数、共享过滤参数、TOGL 插在第 1 个位置（models.py:631-649）。论文补充材料与代码默认的过滤隐藏维度存在 32 对 24 的差异。
  • PH 核心由外部 C++ 扩展提供，本仓库没有重写其数学算法；当前恢复只做静态源码与文档验证，没有重跑论文训练或复现表格数值。
  • 方法仅实现 0、1 维拓扑，因此覆盖连通分量与环，不覆盖高维空腔，也不学习多参数过滤之间的联合拓扑交互。

TOGL: Topological Graph Neural Networks

Paper: Horn et al. (2022) “Topological Graph Neural Networks”, ICLR 2022 arXiv: 2102.07835 Code: https://github.com/BorgwardtLab/TOGL Authors: Max Horn, Edward De Brouwer, Michael Moor, Yves Moreau, Bastian Rieck, Karsten Borgwardt

Motivation & Novelty

The Problem

Standard message-passing GNNs are provably no more powerful than the Weisfeiler-Lehman (WL[1]) graph isomorphism test (Xu et al. 2019, ICLR). WL[1] cannot distinguish graphs with identical local neighborhoods but different global topology — for example, a hexagon vs. two triangles, or “necklace” structures that differ in how their cycles connect. This is not merely theoretical: molecular graphs contain critical topological features (aromatic rings, fused ring systems, bridged bicyclics) that standard GNNs struggle to encode.

Existing topology-based methods addressed this partially:

  • GFL (Hofer et al. 2020, ICML): Uses GNN output as filtration input for a topological readout function — topology only at the end, cannot inform intermediate GNN layers
  • PersLay (Carrière et al. 2020, AISTATS): Fixed, non-learnable filtration functions; not integrated into GNN layers
  • Zhao et al. (2020, AISTATS): Uses topology for scalar edge weights only; local neighborhoods; static vectorization

What TOGL Contributes

  1. Topology-aware layer, not readout: TOGL can be inserted anywhere in a GNN stack, making topological information available to all downstream layers
  2. Multiple learnable filtrations: Learns $k$ different filtrations jointly end-to-end (vs. single fixed or single learned filtration)
  3. Strict expressivity guarantee: TOGL is provably more powerful than WL[1] (Theorem 2) while maintaining compatibility with any GNN backbone
  4. Generic integration: Drop-in replacement for any GNN layer — GCN, GIN, GAT all tested

Method Overview

TOGL is a differentiable GNN layer that augments node representations with persistent homology features computed from learnable graph filtrations.

Core idea: Train an MLP to assign scalar values to nodes, use those values to define a sequence of nested subgraphs (filtration), track which connected components and cycles are created/destroyed as nodes are added (persistent homology), and encode these topological features back into node embeddings.

Pipeline (see doc_method.md for full derivation):

  1. Filtration learning: Shared MLP $\Phi: \mathbb{R}^d \to \mathbb{R}^k$ maps node features to $k$ scalar filtration values per node. Edge values follow max convention.

  2. Persistent homology: For each of $k$ filtrations, compute persistence diagrams $\mathcal{D}^{(0)}$ (connected components, one pair per vertex) and $\mathcal{D}^{(1)}$ (cycles, one pair per cycle-creating edge).

  3. Diagram embedding via coordinate functions (Triangle, Gaussian, Line, RationalHat from Carrière et al.) or DeepSets (novel). These map each (birth, death) pair to a learnable feature vector.

  4. Dim0 integration: Residual addition to node features: $\tilde{x}^{(v)} = x^{(v)} + \text{BN}(\text{ReLU}(\text{Linear}(\Psi^{(0)}[v])))$

  5. Dim1 integration: Cycle features are sum-pooled to graph level and concatenated before the final MLP classifier.

Hyperparameters (paper defaults): $k=8$ filtrations, 3 coordinate functions per type, hidden dim 138–146, share_filtration_parameters=True, inserted at position 1 (GCN-3-TOGL-1).

Expressivity: Two triangles vs hexagon: $\beta_0 = \beta_1 = 2$ vs $\beta_0 = \beta_1 = 1$. WL[1] cannot distinguish; persistent homology trivially can.

Evaluation

Datasets

Synthetic (created by authors):

  • CYCLES: 1000 graphs; class 0 = one large cycle, class 1 = multiple small cycles. Distinguishable by Betti numbers (topology “trivial”)
  • NECKLACES: 1000 graphs; class 0 = two individual cycles, class 1 = “merged” cycle. Same Betti numbers — requires learnable filtrations

Real-world (from TU Datasets / GNN Benchmarks):

  • Graph classification: DD, ENZYMES, PROTEINS-FULL, MNIST, CIFAR-10, IMDB-B, REDDIT-B, NCI1, MOLHIV (ROC-AUC)
  • Node classification: PATTERN, CLUSTER

Key Results

Structure-only experiments (random/no node features — topology matters most):

Method DD MNIST PROTEINS
GCN-4 68.0±3.6 76.2±0.5 68.8±2.8
GCN-3-TOGL-1 75.1±2.1 84.8±0.4 73.8±4.3
GIN-4 75.6±2.8 83.4±0.9 74.6±3.1

TOGL improves GCN by +7% on DD, +8.6% on MNIST, +5% on PROTEINS (structure-only).

Comparison with other topology methods (Table 3):

Method REDDIT-5K IMDB-M NCI1
GFL (ICML 2020) 55.7±2.1 49.7±2.9 71.2±2.1
PersLay (AISTATS 2020) 55.6 48.8 73.5
GCN-1-TOGL-1 56.1±1.8 52.0±4.0 75.8±1.8

Layer depth benefit: On MNIST-structure, GCN-3-TOGL-1 (with 1 TOGL layer) reaches 82.3% accuracy at depth 3, while GCN reaches similar performance only at depth 5. TOGL reduces oversmoothing risk.

Negative result: GAT-3-TOGL-1 on PATTERN drops significantly (59.6% vs 73.1% for GAT-4). TOGL relies on the backbone GNN for filtration quality; poor backbone → poor filtrations.

Reproducibility

Rating: 3/5

Strengths:

  • Code released under BSD-3-Clause at https://github.com/BorgwardtLab/TOGL
  • Uses standard benchmark datasets (pytorch-geometric, TU Datasets)
  • Hyperparameters documented in Appendix E (Table S6), seeds mentioned
  • W&B integration for experiment logging
  • Follows established benchmarking protocol (Dwivedi et al. 2020, arXiv 2003.00982)

Weaknesses / Pitfalls:

  • torch_persistent_homology is an external C++ library that may be difficult to install; no GPU support means training is bottlenecked by CPU PH computation
  • filtration_hidden=32 in Table S6 but code default is 24 — minor discrepancy
  • No instructions for recreating specific comparison numbers beyond the “run train_model.py” level
  • poetry dependency management may create version conflicts; no Docker image provided
  • ENZYMES dataset shows high variance and overfitting — results are not stable across seeds
  • The code requires pytorch-lightning version matching the training setup; API changed significantly between versions

Environment setup:

git clone https://github.com/BorgwardtLab/TOGL
cd TOGL
poetry install
python deps.py  # installs PyG dependencies

Example training:

poetry run python topognn/train_model.py --model TopoGNN --dataset DD \
  --num_filtrations 8 --num_coord_funs 3 --dim1 True \
  --residual_and_bn True --share_filtration_parameters True \
  --depth 4 --togl_position 1

Pertpy: an end-to-end framework for perturbation analysis

pertpy 方法解读：把单细胞扰动分析组织成可组合的 Python 工作流

一句话理解 pertpy

pertpy 不是提出一个单一的新统计模型，而是把单细胞扰动实验中原本分散的步骤——数据获取、元数据补充、gRNA 指派、扰动质量控制、扰动空间构建、距离计算、差异丰度、组成分析、多细胞程序、因果效应和差异表达——统一到 AnnData/MuData 与 scverse 生态中的框架。

因此，读这篇论文时最重要的问题不是“pertpy 的核心公式是哪一个”，而是：它如何让不同类型的扰动数据沿着一致的数据契约流动，并把已有方法的 Python 重实现、性能优化、验证和三个真实用例连接起来。

1. 为什么需要一个框架而不是又一个模型

单细胞扰动可以来自 CRISPR 敲除/激活、药物、疾病状态、温度、感染或组合处理。不同实验产生的分析需求也不同：CRISPR screen 需要判断 guide 是否真正起效，组织治疗数据需要比较细胞组成，药物实验需要连接机制和敏感性数据库，多细胞样本则需要寻找跨细胞类型协调变化。

以往工具通常只覆盖一个环节，且不少原始实现位于 R。研究者要在不同对象格式、包和语言之间搬运数据，很难保持样本、细胞、扰动标签和统计结果的一致性。pertpy 的贡献是建立统一接口：

  • pt.dt 提供扰动数据集加载器；
  • pt.md 把外部数据库元数据附到观测或变量；
  • pt.pp 完成 guide 指派等扰动特异预处理；
  • pt.tl 暴露 Mixscape、distance、Milo、scCODA、DIALOGUE、Augur、CINEMA-OT、差异表达和扰动空间；
  • 结果尽量回写到 AnnData/MuData 的 .obs、.var、.layers、.obsm、.uns 或新的 modality 中。

Fig. 1 正是这个数据流：左侧从不同扰动类型和高维细胞数据出发，经元数据注释、预处理和扰动空间转换；右侧不是单一路径，而是一组可选择的知识推断任务。pertpy 是“工具箱加数据契约”，不是要求每个数据集都顺序运行所有模块。

2. 第一层：把实验标签变成可信的细胞级扰动

2.1 gRNA 指派

在 pooled CRISPR screen 中，每个细胞的 guide RNA 计数需要转成扰动标签。pertpy/preprocessing/_guide_rna.py 的 GuideAssignment 提供两类直接规则：按计数阈值指派，或选择计数最大的 guide。另一个 _guide_rna_mixture.py 使用 Poisson-Gaussian mixture，以概率模型区分背景和真实 guide 信号。

这一步的输出仍然只是“细胞检测到某个 guide”，不等于靶基因产生了功能扰动。guide 捕获、转录效率和细胞逃逸都会造成“被靶向但未被有效扰动”的细胞。

2.2 Mixscape：把 KO 与 NP 分开

pertpy 重实现 Mixscape，先计算每个细胞的扰动签名，再对同一靶标内的细胞做 KO/NP 分类。对于细胞 $c$，近邻模式先在对照池中找到表达状态最接近的 $k$ 个细胞（默认 $k=20$），用其平均表达作为局部参考：

\[s_c = \log(1+\bar{x}_{\mathrm{control,NN}(c)})-x_c.\]

代码 pertpy/tools/_mixscape.py 的 perturbation_signature() 使用 PyNNDescent 查询控制近邻，把结果写入 .layers["X_pert"]。它还支持 split_by 模式：同一 GEM group 或 replicate 内的全部控制细胞共同形成参考。两种方式解决的偏差不同：近邻参考更强调局部状态匹配，分组参考更明确控制实验批次。

随后 mixscape() 为每个靶标寻找差异基因，把细胞投影到扰动方向，并以双组分 Gaussian mixture 估计成功扰动概率。结果包括靶标级 KO/NP 标签、全局类别和后验概率。它并不会证明分子靶点真的被完全敲除，而是依据转录签名将明显响应者和非响应者分开。

Fig. 2a 显示原始 Norman CRISPRa 数据的扰动状态、细胞周期和 GEM group 交织。Extended Data Fig. 2 对比近邻参考、GEM-group 参考和不使用 Mixscape 的处理，说明预处理选择会改变后续扰动空间的清晰度。

3. 第二层：从细胞空间构造“扰动空间”

普通 PCA/UMAP 优先解释细胞之间最大的变化，未必突出扰动身份。pertpy 的 perturbation space 把问题改写为：如何为每个扰动得到可比较的表示？框架提供多种策略，而不是宣称某一种始终最佳。

3.1 Pseudobulk 与 centroid

Pseudobulk space 按扰动聚合表达，减少单细胞噪声；centroid space 在已有低维表示中计算每组中心，并可选择最接近中心的实际点。二者简单、可解释，适合做基线和距离分析，但可能掩盖同一扰动内部的多模态响应。

3.2 分类器空间

MLP classifier space 训练网络从细胞表达预测扰动标签。若网络能够区分扰动，倒数第二层就应保留与扰动身份相关的特征。论文描述的结构可概括为：

\[x \rightarrow \mathrm{Dense}(512) \rightarrow \mathrm{BatchNorm} \rightarrow \mathrm{ReLU} \rightarrow \mathrm{Dense}(K),\]

其中 $K$ 是扰动类别数，训练目标为交叉熵。之后把隐藏层表示按扰动聚合，形成扰动级 embedding。pertpy/tools/_perturbation_space/_discriminator_classifiers.py 的实际实现基于 JAX/Flax 与 Optax，支持逆类别频率加权采样、验证损失早停和 integrated gradients 解释。

这里存在需要保留的论文—代码差异：论文文字称实现基于 PyTorch，并给出 batch size 256、最多 40 epochs；当前代码 commit 使用 JAX/Flax，默认 batch size 128、最多 20 epochs。代码是当前可执行行为，论文参数是论文实验描述，二者不能混写成一个默认值。论文称“oversampling”，代码更准确地说是按逆类别频率 weighted sampling。

框架还包括 logistic-regression classifier、DBSCAN 和 k-means 空间。分类器表示擅长突出可区分扰动，但也可能学习技术或批次信号，因此必须在建模前控制混杂，并通过特征归因和已知 gene program 检查语义。

3.3 Norman 用例如何读

Fig. 2b 将 Norman 的单基因与组合 CRISPRa 扰动投影到 MLP 扰动空间。已知 gene programs 形成簇，原来的 pro-growth 类被拆成 KLF 与 MAPK 相关子簇；一个未注释簇通过通路富集被联系到中性粒细胞脱颗粒。图的证据是“扰动表示能重组已有标签并提出可解释细分”，不是发现了新的因果调控网络。

4. 第三层：用距离回答“两个扰动有多不同”

pertpy 把距离看作独立分析层。pertpy/tools/_distances/_distances.py 统一多类度量：

  • 均值型：MSE、Euclidean、MAE、cosine、Pearson、Spearman、Kendall；
  • 分布型：energy distance、MMD、Wasserstein；
  • 逐基因统计型：t-test、KS、对称 KL、negative-binomial likelihood；
  • 分类器型：两个群体是否可被分类器分开。

例如均值平方误差为：

\[d_{\mathrm{MSE}}(X,Y)=\frac{1}{G}\sum_{g=1}^{G} (\bar{x}_g-\bar{y}_g)^2.\]

Energy distance 同时利用组间与组内距离：

\[E(X,Y)=2\delta_{XY}-\delta_X-\delta_Y,\]

所以能感知整个细胞分布，而不只比较均值。MMD 用核函数比较分布；Wasserstein 由 OTT-JAX 的 Sinkhorn 求解。选择指标时应从生物问题出发：只关心平均响应时 pseudobulk 指标足够；关心异质性时需分布指标；高维小样本下则要注意距离集中和估计不稳定。

DistanceTest 为距离增加 Monte Carlo permutation test，默认执行 1000 次置换，并用 Holm–Šidák 校正多重检验。它回答的是“观测距离相对于标签可交换的零假设是否异常”，而不是直接给出效应的生物重要性。

5. 第四层：针对不同生物问题选择专门模型

5.1 scCODA / tascCODA：细胞组成变化

对样本 $s$ 的 $K$ 类细胞计数，scCODA 使用 multinomial logistic 模型：

\[y_s\sim\mathrm{Multinomial}(n_s,\pi_s),\qquad \log\frac{\pi_{s,k}}{\pi_{s,\mathrm{ref}}} =\alpha_k+x_s^\top\beta_k.\]

参考细胞类型处理组成数据的总和约束，稀疏先验用于识别可信变化。pertpy 的 Sccoda/Tasccoda 基于 JAX、NumPyro NUTS 和 MuData；tascCODA 进一步利用细胞类型树共享信息。结果是相对组成效应，解释必须依赖参考类型，不能把它当作各类型独立的绝对细胞数变化。

5.2 Milo：连续状态中的差异丰度

Milo 在 KNN 图上构建重叠邻域，统计每个样本对邻域的细胞贡献，再用计数模型测试条件差异。它适合连续细胞状态，避免先硬切成离散 cluster。pertpy/tools/_milo.py 以 MuData 同时管理表达 modality 与 neighborhood-level 结果。

5.3 Augur：哪个细胞类型对扰动最敏感

Augur 在每个细胞类型内训练分类器预测 treatment/control。可分性高说明该类型的分子状态对处理更敏感；分类结局使用 AUC，连续结局使用 concordance correlation。pertpy 的 Augur 支持随机森林或逻辑回归、多轮交叉验证与 joblib 并行。高 AUC 表示“处理标签可预测”，不自动等于该细胞类型是因果驱动者。

5.4 DIALOGUE：跨细胞类型的协调程序

DIALOGUE 先对各细胞类型构建样本级表示，再用 sparse CCA 找到跨细胞类型相关的 multicellular programs（MCPs），随后回到细胞层面计算 MCP 分数、校正计数深度，并用混合效应模型测试基因关联。pertpy/tools/_dialogue.py 使用 sparsecca，提供 binary-search 与 linear-programming 求解路径，并以 mixed-effects model 处理样本结构。

MCP 是跨细胞类型共同变化轴，并不单独给出配体—受体因果关系。若据此提出细胞通讯机制，还需要外部知识与实验验证。

5.5 CINEMA-OT：估计单细胞处理效应

CINEMA-OT 试图把处理细胞与潜在反事实控制细胞匹配，从而把处理效应与混杂变化分开。pertpy 的 Cinemaot 使用独立成分分析构造混杂表示，并以 OTT-JAX optimal transport 计算匹配。论文的验证报告：对转换后的混杂量，相对 Frobenius norm 差异为 0.0973；单基因处理效应与原实现的平均 Pearson 相关为 0.989、Spearman 为 0.983。它依赖“可由观测数据恢复足够混杂结构”等识别假设，不能把 OT 匹配直接解释为随机实验。

5.6 差异表达与富集

统一的 differential expression 层通过公式和 contrast 接口连接 PyDESeq2、edgeR、statsmodels、Wilcoxon 和 t-test。edgeR 后端仍需要 R/rpy2，因此“Python 框架”不代表所有后端完全没有外部运行时。Enrichment 模块连接 Drug2Cell 与 blitzGSEA，把差异结果转为通路或药物机制查询。

6. 元数据不是装饰，而是分析变量

pertpy 的 metadata 模块将 DepMap、GDSC、PRISM、CMap、PubChem、ChEMBL 等来源连接到细胞系、药物、化合物和作用机制。代码位于 pertpy/metadata/，例如 _cell_line.py 的 annotate_from_gdsc() 和 annotate_from_prism()，以及 _moa.py、_drug.py、_compound.py。

Fig. 3 的 MIX-Seq 用例展示为什么这一步重要。154,710 个细胞覆盖 172 个细胞系和 13 种药物。作者先用外部 metadata 标注组织谱系、作用机制和药物敏感性，并以 CCLE bulk expression 做一致性检查（图中平均 Pearson 约 0.876）。然后针对 dabrafenib，按细胞系计算处理相对控制的 log fold change，并对每个基因拟合：

\[\log\mathrm{FC}_g=\beta_{0,g}+\beta_{1,g} \times \mathrm{DabrafenibSensitivity}.\]

截距 $\beta_0$ 表示不随敏感性变化的响应，斜率 $\beta_1$ 表示随敏感性增强的响应。Fig. 3c–d 分别展示两类基因及其通路富集。这个分解依赖跨细胞系线性关系和外部敏感性质量；它不是 pertpy 内置的普适因果模型，而是用 pertpy 模块组合出的论文用例。

7. TNBC 用例：同一数据上组合多个问题

Fig. 4 分析乳腺癌新辅助化疗与 anti-PD-L1 联合治疗前后的免疫细胞。这里三个模块回答三个不同问题：

  1. PCA 表示上的 MSE distance 比较组间整体表达差异；
  2. scCODA 检测 CD4 central memory、CD8 effector memory、CD8 tissue-resident memory 等细胞比例的可信变化；
  3. DIALOGUE 寻找跨细胞类型且与治疗反应相关的 MCP，论文进一步讨论 IL-7/IL-7R 与 AP-1 相关基因。

Fig. 4c 显示化疗组的稳定疾病与部分反应在治疗前后距离变化更明显，而组合治疗组模式不同；Fig. 4d 的红星是 scCODA 的 credible effects。Extended Data Fig. 4–5 提供 MCP2 与反应、细胞类型特异基因的支持。三种分析结果互补，但它们分别对应表达距离、组成和跨细胞程序，不能合并成单一“疗效机制分数”。

8. 论文如何验证重实现

pertpy 的价值很大部分来自把已有 R 或独立 Python 方法整合进统一框架，因此“是否复现原方法”比新颖公式更关键。论文与补充材料报告：

  • Mixscape 扰动分数相关约 0.97，KO/NP 分类高度一致；
  • scCODA 参数和 log2 fold change 接近原实现；
  • Milo 与 miloR 的结果相关约 0.987；
  • CINEMA-OT 的处理效应达到 Pearson 0.989、Spearman 0.983；
  • Augur 各细胞类型 AUC 基本位于原 R 包结果的 4% 误差带内。

Extended Data Fig. 1 在 5,000 到 1,000,000 细胞范围比较运行时间和内存。benchmark 由 pertpy-reproducibility/benchmark/ 的 Snakemake 与隔离环境实现。速度提升来自 JAX/NumPyro、并行化、PyNNDescent 和稀疏计算等多种工程选择，不能简单归因于“Python 比 R 快”。不同方法的算法、依赖和硬件路径也不同。

9. 代码与论文的真实边界

本工作区包含两个互补代码目录：

  • pertpy/：框架主仓库，commit f47072b9a5721c8a2e8be2b3a980ef8cd5ec88b4；
  • pertpy-reproducibility/：三套用例、runtime benchmark、Snakemake 和环境定义。

这不是 source mismatch。论文的 Code availability 本身同时指向 scverse/pertpy 和复现仓库。主仓库回答“API 如何实现”，复现仓库回答“论文图和 benchmark 如何运行”。

仍需保留以下边界：

  • 框架包含很多源方法，pertpy 的高层接口并不消除各方法自身的统计假设；
  • 三个用例主要由 notebooks 组织，不是一条统一 CLI；
  • 数据加载器能下载公开数据，但大规模数据和外部数据库会发生版本漂移；
  • JAX、NumPyro、OTT-JAX、PyTorch、rpy2/R 等构成较重依赖矩阵；
  • 论文实验使用 pertpy 0.10.0，而本地源码 commit 代表取得时的仓库状态，默认值可能随版本变化；
  • doc_code.md 记录了 MLP 实现语言和超参数差异，解释当前行为时应优先直接代码，复述论文实验时应保留论文参数。

10. 一条实际可用的分析路线

面对新的扰动数据，不应机械调用全部模块。更合理的决策顺序是：

  1. 明确观测单位、扰动标签、对照、样本和批次；
  2. CRISPR 数据先验证 guide 指派，再用 Mixscape 或独立证据检查是否真正响应；
  3. 选择与问题匹配的表示：均值效应用 pseudobulk，异质性保留单细胞分布，扰动可分性可用 classifier space；
  4. 距离分析同时报告效应量、置换检验和分层敏感性；
  5. 组成变化用 scCODA/tascCODA，连续状态差异丰度用 Milo；
  6. 细胞类型响应排序用 Augur，跨类型协调用 DIALOGUE，反事实效应问题才考虑 CINEMA-OT；
  7. 外部 metadata 的版本、匹配率和缺失值应作为正式质量控制，而非默默合并；
  8. 用独立实现或已知生物标签验证结果，特别是从一种生态重实现的方法；
  9. 保存 AnnData/MuData 中每个中间字段的来源，避免 .obs 或 .uns 键被后续步骤误用；
  10. 把框架运行成功与生物学结论成立分开报告。

11. 怎样正确概括 pertpy 的贡献

pertpy 的强项是广度、互操作性与工程验证：它把多种扰动类型、外部知识和成熟统计方法放在一致的 Python 对象模型中；为原先 R-only 的方法提供经过数值比较的实现；还用可复现仓库把三类真实问题串起来。

它的限制也来自同一设计：模块越多，统计假设和依赖越异质；框架无法替代研究者为数据选择合适模型；论文中的生物发现主要是用例示范，而不是某个全新算法带来的普适突破。最准确的说法是：pertpy 降低了构建严谨扰动分析工作流的工程成本，但不会自动保证扰动标签可信、混杂已消除或因果解释成立。

Pertpy: An End-to-End Framework for Perturbation Analysis

Paper Information

  • Title: Pertpy: an end-to-end framework for perturbation analysis
  • Authors: Lukas Heumos, Yuge Ji, Lilly May, Tessa D. Green, Stefan Peidli, Xinyue Zhang, et al. (29 authors)
  • Journal: Nature Methods, 2025
  • DOI: 10.1038/s41592-025-02909-7
  • Code: https://github.com/scverse/pertpy (Apache 2.0)
  • Documentation: https://pertpy.readthedocs.io

Motivation & Novelty

Single-cell perturbation experiments have grown rapidly in scale and complexity — from early CRISPR screens to genome-scale Perturb-seq datasets with millions of cells and thousands of perturbations. Existing analysis frameworks suffer from critical limitations:

  • MUSIC (Wang et al., Nature Communications, 2019), ScMAGeCK (Yang et al., Genome Biology, 2020), SCEPTRE (Barry et al., Genome Biology, 2021), GSFA (Zhou et al., Nature Methods, 2023), and FR-Perturb (Yao et al., Nature Biotechnology, 2024) focus exclusively on CRISPR screen analysis, neglecting drug treatments, disease states, and other perturbation types
  • Many tools are R-only (e.g., miloR, DIALOGUE, Augur), fragmenting the Python single-cell ecosystem
  • No framework provides integrated metadata enrichment from databases like DepMap, GDSC, CMap, PubChem, and ChEMBL
  • No framework offers standardized perturbation distance metrics with statistical testing
  • Scalability is limited for datasets exceeding 100K cells

Pertpy’s unique contributions:

  1. Unified framework: First Python package to integrate perturbation-specific preprocessing (Mixscape), embedding (6 perturbation space methods), analysis (distances, compositional analysis, multicellular programs, causal inference), and evaluation in a single coherent pipeline
  2. Metadata contextualization: Automated annotation from 5 external databases (DepMap, GDSC, CMap, PubChem, ChEMBL) enables biology-informed analysis that connects perturbation effects to known drug mechanisms and cell line characteristics
  3. Distance metric library: 20 distance/divergence metrics with Monte Carlo permutation testing — the most comprehensive collection for perturbation comparison, benchmarked in Ji et al. (2024)
  4. Performance: JAX-accelerated implementations of scCODA, tascCODA, DIALOGUE, Mixscape, and others run substantially faster than original R implementations (Extended Data Fig. 1)
  5. scverse integration: Built on AnnData/MuData within the scverse ecosystem, ensuring interoperability with scanpy, scvi-tools, squidpy, and other community tools
  6. Community re-implementations: Brought R-only methods (Milo, Augur, DIALOGUE) to Python with verified numerical agreement

Method Overview

Pertpy provides a modular pipeline for perturbation analysis, organized into 5 stages:

  1. Data & Metadata: 45+ public datasets with automated enrichment from biological databases
  2. Preprocessing: gRNA assignment (2 methods), Mixscape (perturbation QC), batch correction integration
  3. Perturbation Spaces: 6 embedding methods (MLP classifier, logistic regression, pseudobulk, centroid, DBSCAN, k-means) to learn lower-dimensional perturbation representations
  4. Downstream Analysis: 20 distance metrics, Bayesian compositional models (scCODA/tascCODA), neighborhood testing (Milo), multicellular programs (DIALOGUE), causal inference (CINEMA-OT), cell type prioritization (Augur), differential expression (PyDESeq2/edgeR), pathway enrichment (blitzGSEA)
  5. Evaluation: Monte Carlo permutation testing, integrated gradients for feature importance, evaluation metrics for perturbation prediction models

See doc_method.md for mathematical details and doc_code.md for implementation specifics.

Evaluation

Use Case 1: CRISPRa Screen (Norman et al., Science, 2019)

  • Dataset: 111,255 K562 cells under 287 single/combinatorial gene perturbations
  • Compared 3 preprocessing strategies: KNN-based Mixscape, GEM-group-based Mixscape, and no filtering
  • MLP classifier space revealed gene program clusters with refined annotations (pro-growth → KLF vs MAPK subclusters)
  • Identified unannotated cluster with neutrophil degranulation pathway downregulation
  • Integrated gradients confirmed classifier prioritizes targeted genes (e.g., KLF1 for pro-growth)

Use Case 2: Chemical Perturbation (McFarland et al., Nature Communications, 2020)

  • Dataset: 154,710 cells from 172 cell lines × 13 drugs (MIX-Seq)
  • Metadata enrichment: DepMap, GDSC, CMap, CCLE profiles (Pearson r = 0.88 with CCLE)
  • Viability deconvolution of dabrafenib: identified cancer-linked genes (ETV4, CDKN2D, MYEOV) in drug response
  • Viability-dependent genes enriched in interferon signaling; viability-independent genes in protein translation

Use Case 3: TNBC Treatment (Zhang et al., Cancer Cell, 2021)

  • Dataset: 489,490 immune cells from 22 TNBC patients (NACT ± anti-PD-L1)
  • MSE distance: NACT responders showed greater pre/post-treatment distance than combination therapy
  • scCODA: Compositional shifts in CD4 central memory, CD8 effector memory, CD8 tissue-resident memory T cells for NACT only
  • DIALOGUE MCP2: Associated with treatment response across cell types; IL-7/IL-7R interaction and AP-1 complex genes (JUN, FOS, FOSB) implicated

Runtime Benchmarks

All re-implemented methods showed substantial speedups over original implementations (Extended Data Fig. 1). JAX-accelerated scCODA 2.0 and tascCODA 2.0 with NumPyro NUTS sampler; Mixscape with PyNNDescent; DIALOGUE with sparsecca Python implementation.

Verification

Each re-implementation was rigorously verified against the original:

  • Mixscape: 97% correlation in perturbation scores; high confusion matrix agreement (4,674 KO + 13,098 NP matched)
  • scCODA: Parameter estimates within ~0.01; log₂ fold changes within ~0.005
  • Milo: r = 0.987 correlation with miloR
  • CINEMA-OT: Relative Frobenius norm < 0.1; gene-level Pearson r = 0.989
  • Augur: AUC scores within 4% of R package

Reproducibility

Rating: 4/5 (Excellent)

Strengths:

  • Full source code on GitHub under Apache 2.0 license with comprehensive documentation
  • Dedicated reproducibility repository (pertpy-reproducibility) with Jupyter notebooks for all three use cases
  • Conda environment file for exact dependency reproduction
  • Snakemake pipeline for runtime benchmarking with per-tool isolated environments
  • All datasets are publicly available with built-in data loaders (GEO, figshare)
  • Verified numerical agreement with original R implementations

Weaknesses:

  • Large dependency footprint (JAX, NumPyro, OTT-JAX, PyTorch, rpy2 for edgeR) complicates installation
  • Some analyses require significant memory (genome-scale Perturb-seq datasets)
  • Reproducibility notebooks reference external datasets that require download

Practical notes:

  • Install via pip install pertpy (PyPI)
  • GPU acceleration requires JAX with CUDA support
  • edgeR backend requires R + rpy2 setup
  • tascCODA requires ete4/toytree for tree visualization

Strengths and Weaknesses

Strengths

  1. Comprehensive coverage: Most complete perturbation analysis framework available, spanning data loading through statistical testing
  2. Community-driven: Part of scverse ecosystem with 29 authors including original method developers
  3. Principled verification: Each re-implementation numerically verified against original
  4. Well-documented: Extensive tutorials (>15 use cases), API documentation, and reproducibility notebooks
  5. Scalable: JAX/NumPyro acceleration; handles genome-scale datasets
  6. Metadata integration: Automated biological context enrichment from 5 databases

Weaknesses

  1. Framework, not method paper: No novel algorithmic contributions — value is in integration, re-implementation, and metadata
  2. Limited novel evaluation: Use cases reproduce or extend original analyses rather than demonstrating new biological discoveries
  3. MLP classifier is simple: Feed-forward MLP for perturbation embedding; no comparison to more sophisticated approaches (VAEs, transformers)
  4. Spatial not yet integrated: Acknowledged limitation — spatial perturbation analysis planned but not implemented
  5. Memory constraints: Out-of-memory computation (Dask) noted as future work for 100M+ cell datasets
  6. Paper-code inconsistencies: MLP described as PyTorch but implemented in JAX/Flax; hyperparameter defaults differ from paper

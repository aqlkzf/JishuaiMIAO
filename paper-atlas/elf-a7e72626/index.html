ELF: Embedded Language Flows

Open paper Code

ELF：在上下文词嵌入空间中生成文本

先给出结论

ELF（Embedded Language Flows）不是逐 token 自回归，也不是在离散词表上反复掩码和去噪。它先用冻结的 T5-small 编码器把整段文本变成连续、带上下文的 token 表示，再学习一个从高斯噪声到这些表示的 rectified flow。采样过程中状态一直是连续向量；只有到最终时刻，才由与去噪器共享主干的解码头一次性映射回词表。

这项工作的真正组合创新有三点：上下文化嵌入提供了比静态词向量更适合连续插值的几何空间；一个网络同时承担连续去噪和最终离散解码；训练期 CFG 把条件/无条件引导蒸入目标，使推断时每一步只需一次网络前向。论文是 2026 年 arXiv 预印本，下面的效果结论应按预印本证据理解。

1. 为什么不直接在 token 上做连续扩散

文本 token 是离散类别。若给每个 token 一个静态向量并直接加噪，相邻向量未必有相近语义，而且同一个词在不同句子中的含义无法变化。ELF 采用冻结的 T5-small encoder：输入完整 token 序列后，为每个位置生成 512 维上下文化表示 $x$。因此，同一 token 会因左右文不同落在不同位置，连续轨迹也更可能沿有意义的语言表示移动。

这里要区分两个层次：T5 编码器只负责定义目标表示空间；ELF 网络负责从噪声生成该空间中的序列。论文和代码都没有声称端到端更新 T5，也不能把 ELF 简化为“在原始词表 embedding 上扩散”。

2. 核心流匹配目标

从目标上下文表示 $x$ 和同形状高斯噪声 $\epsilon$ 构造直线路径：

\[z_t = t x + (1-t)\epsilon,\qquad t\in[0,1].\]

该路径的真实速度为：

\[v = \frac{\mathrm d z_t}{\mathrm d t}=x-\epsilon.\]

模型看到带噪状态 $z_t$、时间 $t$，以及条件任务中的上下文，预测干净表示 $\hat{x}_\theta(z_t,t)$。代码再把 clean prediction 换算为速度用于积分；接近 $t=1$ 时会对分母做截断，避免数值不稳定。训练的连续分支等价于让预测速度逼近 $x-\epsilon$：

\[\mathcal L_{\mathrm{MSE}} =\mathbb E\left[\|v_\theta(z_t,t)-v\|_2^2\right].\]

这条直线路径是 rectified flow 的训练路径，不意味着生成轨迹在模型近似误差下必然是精确直线。

3. 一个共享主干，两种训练模式

ELF 不是独立训练“扩散模型 + 另一个词表解码器”。同一个 Transformer 主干在两类 batch 上工作：

  1. 连续去噪分支（约 80%）：随机采样时间与噪声，最小化流匹配 MSE，学习从 $z_t$ 恢复干净上下文表示。
  2. 最终解码分支（约 20%）：把接近干净表示的输入送入共享网络，在 $t=1$ 通过 factored unembedding 输出词表 logits，以交叉熵学习原 token。

这种联合训练使最终离散化器见过模型自身需要处理的表示分布，而不是把一个独立、事后训练的最近邻解码器接上去。代码中的模型模式不是一个简单标量开关：解码模式可加入可学习 mode token；时间 token、可选 CFG token 和 mode token 都作为前缀进入主干，RoPE 只施加到实际序列位置。

最终词表头是分解投影：隐藏维先投影回文本编码维，再投影到词表。src/modules/model.py 在两次线性映射之间实际使用 GELU；论文只概括为 factored unembedding，没有写出这一激活细节。

4. 为什么解码分支也要加噪

若解码器只见过完美 T5 表示，推断时面对流模型产生的轻微偏移可能失效。ELF 因而在解码训练中加入逐 token 的 logit-normal 噪声时间，且解码分支噪声尺度高于连续分支。这样解码头学习把“接近语义流形但不完全等于编码器输出”的向量还原成 token。

论文给出的设置是去噪噪声尺度 2、解码噪声尺度 5。这里的逐 token 噪声意味着一个句子不同位置可以有不同扰动强度；它不是生成时逐位置依次解码。

5. 自条件与训练期 CFG

自条件

训练时以 0.5 概率先获得一次干净表示预测，再将其作为额外条件输入下一次预测。推断也可把上一积分步的预测传给下一步。这让网络利用自身先前估计，但不会改变“一直到最后才离散化”的原则。

训练期 classifier-free guidance

普通 CFG 在每个采样步分别计算条件和无条件输出，再线性组合，因此一条轨迹每步要两次前向。ELF 在训练期构造引导目标，把这一组合行为教给单个条件前向；引导强度作为 token 输入网络。论文的目标形式为：

\[v_{\mathrm{target}} =v+\left(1-\frac{1}{\omega}\right)(v_{\mathrm{cond}}-v_{\mathrm{uncond}}).\]

因此推断时可用一次前向完成带引导更新。图 4 与条件生成实验显示，引导强度改变生成质量与多样性的折中；它不是一个只会单调改善所有指标的免费旋钮。

6. 网络与代码中的实现细节

共享 ELF Transformer 先用 BottleneckTextProj 将 512 维 T5 表示经瓶颈投影到模型隐藏维；时间、CFG 和模式信息成为前缀 token。主干使用 RMSNorm、旋转位置编码、注意力和 SwiGLU FFN，最后零初始化的输出层预测干净嵌入。

代码提供 ELF-B、ELF-M、ELF-L 三个规模，分别约为 12/24/32 层，隐藏维 768/1056/1280。直接代码还揭示了论文正文未展开的工程选择：dropout 只施加在中间一半层；EMA 只在真实优化器更新步执行，而非梯度累积的每个 microbatch；训练 RNG 的固定拆分兼顾已发布 checkpoint 的复现。这些是实现事实，不应反向写成论文明确提出的方法贡献。

7. 推断：连续积分，末端一次离散化

推断从 $z_0\sim\mathcal N(0,I)$ 开始，在选定时间网格上重复：网络预测 clean embedding，将其换算成速度，再更新连续状态。代码支持两类更新：

  • ODE：按预测速度作确定性积分。
  • SDE-inspired：在更新时重新注入噪声，以增加随机性和样本多样性。

论文谨慎称后者为 SDE-inspired 的简单近似，所以不能把代码路径描述成严格求解了某个完整推导的反向 SDE。积分结束到 $t=1$ 后，factored unembedding 输出 logits，再取 token。图 17 虽把中间连续状态临时解码以展示轨迹演化，那只是诊断可视化；标准生成算法并未在每一步把状态量化成 token 再继续。

10. 最适合记住的一条数据流

\[\text{tokens} \xrightarrow{\text{frozen T5 encoder}} x \xrightarrow{\text{linear noising}} z_t \xrightarrow{\text{shared ELF Transformer}} \hat{x},\hat{v} \xrightarrow{\text{ODE/SDE-inspired integration}} z_1 \xrightarrow{\text{shared factored decoder}} \text{tokens}.\]

理解 ELF 时最容易犯的错误，是把它看成“每一步都生成 soft token”。更准确的说法是：训练目标来自上下文化 token 表示，但采样状态始终保持为连续向量，最终一步才通过联合训练的共享解码头回到离散词表。

ELF: Embedded Language Flows — Summary

Motivation & Novelty

Problem: Language generation requires producing discrete token sequences from a learned distribution. Diffusion/flow models excel at continuous data (images, video) but face a fundamental interface challenge with discrete language: how to operate in continuous space while ultimately producing discrete outputs.

Why existing methods fall short:

Method Limitation Journal/Year
Diffusion-LM (Li et al.) Per-step CE loss at every denoising step; trajectory tied to token space NeurIPS 2022
CDCD (Dieleman et al.) Per-step vocabulary supervision; Score-ODE formulation arXiv 2022
DiffuSeq (Gong et al.) Per-step rounding/CE; trained embeddings jointly ICLR 2023
MDLM (Sahoo et al.) Discrete — inherently limited for continuous techniques like CFG NeurIPS 2024
Duo (Sahoo et al.) Discrete (uniform-state) — less effective CFG ICML 2025
FLM/FMLM (Lee et al.) Per-step supervision on one-hot encodings; distillation needed for few-step arXiv 2026
LangFlow (Chen et al.) Per-step supervision in embedding space; Bregman FM arXiv 2026
LD4LG (Lovelace et al.) Separate decoder required; DDPM noise schedule NeurIPS 2023

What’s new in ELF:

  1. Final-step-only discretization: The denoising trajectory is unrestricted continuous throughout; only at $t=1$ does the model switch to token prediction. No per-step CE supervision during training, no nearest-neighbor rounding during inference.
  2. Shared-weight denoiser-decoder: The same network serves as denoiser ($t < 1$) and decoder ($t = 1$), eliminating the need for a separately trained decoder.
  3. Natural CFG in language: Because ELF operates entirely in continuous space with velocity-field parameterization, classifier-free guidance (a standard technique from image diffusion) applies directly via velocity interpolation. Prior discrete DLMs lack this.
  4. Training-time CFG: Distills CFG guidance into a single forward pass during training; no extra inference cost.
  5. x-prediction essential: Shows that predicting clean embeddings (rather than velocity or noise) is critical for high-dimensional language representations — a finding with theoretical grounding from prior image diffusion work.

Method Overview

ELF is a continuous diffusion language model using rectified-flow (Flow Matching) in the contextual embedding space of a frozen T5-small encoder.

Pipeline:

  1. Tokens → T5-small encoder → clean contextual embeddings $x \in \mathbb{R}^{L \times 512}$
  2. Linear interpolation: $z_t = tx + (1-t)\epsilon$ for $\epsilon \sim \mathcal{N}(0, I)$
  3. ELF network predicts $\hat{x}$ (x-prediction parameterization) → velocity $\hat{v} = (\hat{x} - z_t)/(1-t)$
  4. Training loss: MSE on velocity (80%) + CE on final-step tokens (20%)
  5. Training-time CFG: guided velocity target $v_{\text{target}} = v + (1 - 1/\omega)(v_{\text{cond}} - v_{\text{uncond}})$
  6. Inference: N Euler or SDE steps + final argmax unembedding

Key components:

  • Self-conditioning: Previous prediction $\hat{x}’$ concatenated to $z_t$ with 50% probability
  • In-context conditioning: Time/CFG-scale/mode tokens prepended (not adaLN-Zero)
  • Bottleneck: 512d → 128d → 768d (ELF-B) projection
  • SDE sampler: Per-step noise re-injection with scale γ for error correction

See doc_method.md for mathematical derivations and doc_code.md for code-paper mapping.

Reproducibility Rating: 4/5

Justification:

  • Code is released at https://github.com/lillian039/ELF (JAX/Flax, TPU-oriented)
  • All hyperparameters documented in config YAMLs and Table 4 of the paper
  • Pre-trained T5 encoder and pre-tokenized dataset released on HuggingFace Hub (embedded-language-flows/openwebtext-t5, embedded-language-flows/t5_small_encoder_jax/)
  • Reproducibility confirmed: Table 6 shows ±0.16 standard error at 32 steps over 6 seeds

Limitations (deductions):

  • TPU-specific (v5p × 64) — GPU adaptation required; JAX XLA compilation may have platform differences
  • Decoder baseline reproduction requires reproducing Duo with cross-attention conditioning modification (Table 8)
  • Inference hyperparameters for system comparison (γ=2 at 8 steps, γ=1.5 at 32 steps) require tuning if generalizing

Practical notes:

  • Run src/train.py with appropriate YAML config (src/configs/training_configs/train_owt_ELF-B.yml)
  • Training: 1.5 hours/epoch on TPU v5p × 64; ~7.5h total for ELF-B
  • Inference: Use src/eval.py or src/generation.py; for system comparison use SDE with logit-normal schedule
  • The 11-way RNG split in train_step.py ensures checkpoints are exactly reproducible across resumed runs

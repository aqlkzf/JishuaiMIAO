ISON

Inference of Spatial Chromatin Accessibility via Integration of Spatial Transcriptomics and Single-Cell Multiomics Data

Open paper

ISON 方法中文解读

1. 这篇文章要解决什么问题？

ISON 要解决的是一个空间多组学里的“缺模态”问题：我们通常能比较容易得到空间转录组 ST，也能得到单细胞 multiome 中同一个细胞的 RNA 和 ATAC，但目前广泛可用的商业平台还不能方便地产生同一组织位置上的空间 RNA + 空间染色质可及性联合测量。论文因此提出：用 scRNA-seq、scATAC-seq 和空间 RNA，推断每个空间 spot 的 ATAC 信号，然后用预测出的空间 ATAC 与空间 RNA 做空间基因调控网络分析（paper.md:23-37, paper.md:43-45）。

简单说：

已有数据：
  单细胞 multiome: 同一批细胞有 RNA 和 ATAC
  空间转录组: 每个 spot 有 RNA 和空间坐标

想要补出来：
  每个空间 spot 的 ATAC / chromatin accessibility

再往下做：
  motif 活性、TF 活性、TF-target 网络、疾病相关调控模块

2. 为什么已有方法不够？

论文认为，已有的 ST 整合方法，例如 DestVI、iSORT、STEM，主要是把 scRNA-seq 和 ST 联系起来，对 multiome 层面的调控关系覆盖不足（paper.md:33-35）。在预测空间 ATAC 的 benchmark 中，论文比较了 Tangram、RCTD、SPAGE、GIMVI、CCA+KNN、MOFA 等方法，但也说明这些基线方法很多并不是专门为 multimodal spatial omics integration 设计的，因为这个问题本身还缺少成熟工具（paper.md:55-59, paper.md:363-365）。

ISON 的核心优势不是只做细胞类型映射，而是学习一个能同时解释 RNA、ATAC 和空间 RNA 的低维调控程序表示。

3. ISON 的总体思路

论文说 ISON 有两个模型分支：

  1. joint KL-NMF：用 KL divergence 的非负矩阵分解建模三个计数矩阵。
  2. contrastive joint VAE：用两个 VAE 加 InfoNCE 对比学习做非线性表示学习。

论文最后采用 KL-NMF 作为默认 ISON，因为在 P21/P22 空间 multiome benchmark 中 KL-NMF 表现优于 VAE（paper.md:47-51, paper.md:59-61）。当前公开代码也主要实现了 KL-NMF 分支；VAE/InfoNCE 的自包含实现是 MISSING。

4. 输入、输出和变量

论文的核心输入矩阵定义在 paper.md:121-135。

论文符号 含义 维度 代码变量/来源
$O$ scATAC-seq，可及性矩阵 $P \times N_1$，peak x cell PeakO，来自 test_mu.t()
$E$ scRNA-seq，和 scATAC 同一批 single-cell multiome 细胞 $G \times N_1$，gene x cell X1，来自 train_mu.t()
$E_s$ spatial transcriptomics RNA $G \times N_2$，gene x spot X2，来自 train_sp.t()
coords 空间坐标 $N_2 \times 2$ CSV 的 x, y 两列
$K$ 低维调控程序数量 用户设定 --K，默认 8
$W_1$ peak 对每个调控程序的 loading $P \times K$ W1
$W_2$ gene 对每个调控程序的 loading $G \times K$ W2
$H_1$ single-cell multiome 细胞的程序活性 $K \times N_1$ H1
$H_2$ 空间 spot 的程序活性 $K \times N_2$ H2

代码里，run-ison.py 读取 scRNA、scATAC、ST 和坐标文件，去除线粒体基因，并调用 preprocess.prep() 做两个对齐：scRNA 与 scATAC 取共同细胞 barcode，scRNA 与 ST 取共同基因（code/ISON/run-ison.py:20-54, code/ISON/project/preprocess.py:25-49, code/ISON/project/preprocess.py:70-75）。

最终输出有两个核心矩阵：

\[O_s = W_1H_2\]

它是预测出来的 spatial ATAC（paper.md:201-205, code/ISON/run-ison.py:75-98）。

\[S_{denoised}=W_2H_2\]

它是 denoised spatial RNA（paper.md:207-210, code/ISON/run-ison.py:100-113）。

5. KL-NMF 的共享分解为什么能预测空间 ATAC？

ISON 的关键不是单独分解每个矩阵，而是让三个矩阵共享一部分因子：

\[O \approx W_1H_1\] \[E \approx W_2H_1\] \[E_s \approx W_2H_2\]

解释如下：

  • $O$ 和 $E$ 来自同一批 multiome 细胞，所以它们共享 $H_1$。这让 ATAC 和 RNA 在单细胞层面对齐。
  • $E$ 和 $E_s$ 都是基因表达，所以它们共享 $W_2$。这让 single-cell RNA 与 spatial RNA 的基因程序对齐。
  • 空间数据只有 RNA，所以先用 $E_s \approx W_2H_2$ 学出空间 spot 的低维程序活性 $H_2$。
  • scATAC 的 peak loading 是 $W_1$，所以把 $W_1$ 和空间 spot 的 $H_2$ 相乘，就得到空间 ATAC：$O_s=W_1H_2$。

这就是从 RNA 空间信息推断 ATAC 空间信息的桥梁。代码里 KL_NMF(PeakO, X1, X2, K, ...) 初始化并更新 W1/W2/H1/H2，变量形状来自输入矩阵（code/ISON/project/tri_nmf.py:12-30）。

6. 损失函数：三个 KL 项加空间平滑项

论文使用 KL divergence，因为 RNA/ATAC count 数据被建模为 Poisson-like count 数据（paper.md:137-143）。目标函数是：

\[\min_{W_1,W_2,H_1,H_2} KL(O||W_1H_1) +\mu_1KL(E||W_2H_1) +\mu_2KL(E_s||W_2H_2) +\lambda_2 tr(H_2LH_2^T).\]

每一项的作用：

项 作用    
$KL(O   W_1H_1)$ 让 $W_1H_1$ 重构 scATAC
$KL(E   W_2H_1)$ 让 $W_2H_1$ 重构 scRNA
$KL(E_s   W_2H_2)$ 让 $W_2H_2$ 重构空间 RNA
$tr(H_2LH_2^T)$ 让相邻 spot 的 $H_2$ 更平滑，不要在空间上突然跳变    

这里 $\lambda_1$ 和 $\lambda_2$ 是用户超参数。$\lambda_2$ 控制空间平滑，$\lambda_1$ 控制辅助重构项相对 ATAC 主项的权重（paper.md:149-181）。

7. 为什么要自动计算 $\mu_1$ 和 $\mu_2$？

三个矩阵 $O,E,E_s$ 的规模、稀疏度、总 count 都不同。如果直接给 $KL(E   W_2H_1)$ 和 $KL(E_s   W_2H_2)$ 固定权重，某个矩阵可能因为数值尺度大而支配训练。论文因此先计算三个 naive baseline loss：
\[L_1,\quad L_2,\quad L_3\]

然后用：

\[\mu_1=\frac{L_1\lambda_1}{L_2},\quad \mu_2=\frac{L_1\lambda_1}{L_3}.\]

这样做的直觉是：把 RNA 和空间 RNA 的 KL 项缩放到和 ATAC 主项可比较的尺度。代码对应 l1/l2/l3 和 mu1/mu2 的计算（code/ISON/project/tri_nmf.py:50-77）。

8. platform effects：怎样处理 scRNA、scATAC、ST 的技术差异？

论文在 $W$ 和 $H$ 中加入平台效应项。它的直觉是：不同实验平台之间有系统性差异，需要给模型一个“技术校正通道”，但最后预测生物学信号时要把这些技术项去掉（paper.md:213-215）。

代码实现如下：

  • V1：scRNA 每个 gene 的平均值。
  • V2：ST 每个 gene 的平均值。
  • Vpeak：scATAC 每个 peak 的平均值。
  • F1：single-cell 平台的 one-hot 行。
  • F2：spatial 平台的 one-hot 行。
  • 把这些向量拼到 W10/W20/H10/H20 上（code/ISON/project/tri_nmf.py:32-48）。

训练后，run-ison.py 只保留前 $K$ 个真实程序，再计算：

W1 = W1[:, :k]
H2 = H2[:k, :]
O2_hat = torch.mm(W1, H2)

这一步就是去掉 platform-effect 维度后输出 spatial ATAC（code/ISON/run-ison.py:75-98）。

9. 空间图和 Laplacian：怎样利用坐标？

论文说 ISON 根据 spot 坐标构建空间图：角落点最多 3 个邻居，边缘点最多 5 个邻居，内部点最多 8 个邻居，然后把 adjacency matrix 转成 Laplacian $L$（paper.md:217-219）。

代码里：

  1. run-ison.py 读取坐标文件的 x 和 y 列。
  2. 根据保留下来的 ST spots 过滤坐标。
  3. compute_adjacency_with_limits() 计算 spot 间欧氏距离。
  4. 根据邻居数量分类为 corner/edge/interior。
  5. 构建对称二值 adjacency。
  6. 计算 lapm = degree_matrix - adjacency_matrix（code/ISON/run-ison.py:41-44, code/ISON/run-ison.py:60-63, code/ISON/project/tri_nmf.py:79-84, code/ISON/project/tri_nmf.py:162-206）。

注意：当前代码有可复现性风险。run-ison.py 传入 args.layout，但 parser 定义的是 --lattice；教程写的是 hexagonal，代码接受的是 hex；tri_nmf.py 中函数默认参数 lattice=lattice 没有可见的模块级 lattice 定义（code/ISON/run-ison.py:31-32, code/ISON/run-ison.py:73, code/ISON/grid_layout_tutorial.md:8-19, code/ISON/project/tri_nmf.py:162-179）。

10. 乘法更新：每一步更新什么？

论文给出 $H_1,H_2,W_1,W_2$ 的 multiplicative updates（paper.md:183-198）。代码中对应四个更新块（code/ISON/project/tri_nmf.py:111-136）：

更新量 输入 更新依赖 输出
$H_1$ scATAC mini-batch、scRNA mini-batch、当前 $W_1,W_2,H_1$ ATAC 重构残差 + scRNA 重构残差 新的 single-cell 程序活性
$H_2$ ST mini-batch、当前 $W_2,H_2$、空间 Laplacian ST 重构残差 + 空间平滑项 新的 spot 程序活性
$W_1$ scATAC mini-batch、当前 $H_1$ ATAC 重构残差 新的 peak loading
$W_2$ scRNA mini-batch、ST mini-batch、当前 $H_1,H_2$ scRNA + ST 重构残差 新的 gene loading

代码用 F.relu() 保证更新后的矩阵非负。每轮还打印归一化后的三个 KL 诊断量 dnorm1/dnorm2/dnorm3（code/ISON/project/tri_nmf.py:149-158）。

11. VAE 分支：论文讲了什么，代码缺了什么？

论文的 VAE 分支有两个 VAE：

  • VAE1：输入 scRNA 和 ST，学习 RNA latent space，并处理平台差异。
  • VAE2：输入 scATAC，学习 ATAC latent space。
  • InfoNCE：同一个 single-cell multiome 细胞的 RNA-ATAC pair 是 positive pair，不同细胞是 negative pair。
  • 预测时：把 spatial RNA 经过 VAE1 encoder，再经过 VAE2 decoder，得到 spatial ATAC（paper.md:221-253）。

结构损失定义为：

\[A=E\cdot E_s,\quad B=O\cdot O_s',\quad SL=1-PCC(A,B),\]

其中：

\[O_s'=Dec_{VAE2}(Enc_{VAE1}(E_s)).\]

这些公式在 paper.md:233-275。但是当前公开代码没有自包含的 VAE 类、KL loss、InfoNCE loss 或 structure loss。Benchmark/vae.py 只是加载外部 bemodel_p21.pt、model2_p21.pt，并调用 model2.decoder()；它还依赖缺失的 ./modules_alz/（code/ISON/Benchmark/vae.py:12-23, code/ISON/Benchmark/vae.py:41-47）。因此这里必须保留结论：VAE/InfoNCE implementation is MISSING。

12. 下游 GRN 分析：论文结果和代码证据要分开

论文下游分析包含：

  • 用 chromVAR 从预测 ATAC 计算 motif deviation score。
  • 用 LINGER 结合 ST 和预测空间 ATAC 推断 TF-TG 网络和 TF activity。
  • 对 TF-target 网络做 K-means，得到 12 个调控模块。
  • 用 GSEA 分析疾病、年龄、交互效应相关模块（paper.md:91-97, paper.md:321-323, paper.md:357-361）。

这些是论文和图中的分析结论。当前检查到的公开代码中，非 notebook Python 源码没有 chromVAR/LINGER/K-means/GSEA 的完整实现，所以这部分在代码层面是 Not found。写论文理解时可以讲它们是 ISON 的应用，但不能说它们已经由当前公开代码完整复现。

13. 评估结果怎样理解？

论文主要评估空间 ATAC 预测是否接近真实/观测 ATAC：

  • P21 数据中 KL-NMF 的 mean peak-wise PCC 为 0.23，RMSE 为 1.19；VAE 为 0.09 和 1.22。
  • P22 数据中 KL-NMF 的 mean peak-wise PCC 为 0.15，RMSE 为 0.83；VAE 为 0.07 和 0.84。
  • 因为原始 spatial ATAC 很稀疏，论文还用 MAGIC-imputed ATAC 作为评估对象，P21/P22 的 peak-wise PCC 提升到 0.69/0.63（paper.md:59-61）。

论文进一步用模拟、低基因覆盖、跨数据集预测、Moran’s I、peak-gene distance、eQTL/Hi-C、motif activity 等证明预测 ATAC 保留空间和调控信号（paper.md:63-79）。Figure 2 和 Figure 3 的本地图像也支持这个叙事：ISON 在 benchmark 中 PCC 更高/RMSE 更低，预测 ATAC 的 regulatory signal 更清楚（figure_analysis.md）。

公开代码中的 evaluation.py 覆盖的是较窄的 PCC 评估：读取真实和预测 ATAC，给真实 ATAC 做 log1p 和 MAGIC，对齐 peak/spot，计算 peak-wise、spot-wise 和 flattened Pearson correlation（code/ISON/evaluation.py:20-82）。它没有覆盖论文所有 RMSE、baseline、simulation、GRN 分析。

14. 怎么用一句话理解 ISON？

ISON 的 KL-NMF 分支可以理解为：

用 single-cell multiome 学到“RNA 程序和 ATAC 程序如何在同一细胞中对应”，再用 spatial RNA 学到“每个空间 spot 里有哪些 RNA 程序”，最后把 ATAC 程序投射到这些空间 spot 上，得到预测的 spatial ATAC。

数学上就是：

single-cell multiome:
  O ~= W1 H1
  E ~= W2 H1

spatial transcriptomics:
  E_s ~= W2 H2

prediction:
  O_s = W1 H2

15. 复现时最需要注意什么？

  1. KL-NMF 主分支和论文 Eq.1-Eq.8 匹配度较高，是当前公开代码最可靠的部分。
  2. VAE/InfoNCE 分支是 MISSING，不能从当前代码直接学习或复现实验。
  3. chromVAR/LINGER/GSEA 下游 GRN 管线是 Not found，需要外部脚本、notebook 或作者未发布代码。
  4. run-ison.py 目前存在 args.layout、obs_ratio 等源码级运行风险，需要修补后才能稳定作为 CLI 运行。
  5. 论文是 early-access 未编辑版本，本地 Markdown 来自 MinerU hybrid OCR；应以本地行号为证据，但保留 OCR/早期稿 caveat（paper.md:7-11）。

ISON Summary

Problem

ISON targets a missing data modality problem in spatial omics. Spatial transcriptomics preserves gene-expression location in tissue, and single-cell multiome assays measure RNA plus chromatin accessibility in the same cells, but broadly available commercial assays do not yet profile paired spatial gene expression and epigenomic features in the same experiment (paper.md:23-37). The paper’s goal is to infer spatial chromatin accessibility from sc-multiome and ST data, then use the inferred epigenome with spatial RNA to study spatially resolved gene regulation (paper.md:43-45).

Why Existing Methods Are Not Enough

The paper frames existing ST integration tools such as DestVI, iSORT, and STEM as primarily scRNA-to-ST methods that leave broader multiomic regulatory interactions underexplored (paper.md:33-35). For benchmarking, the authors compare against Tangram, RCTD, SPAGE, GIMVI, CCA+KNN, MOFA, and a VAE branch, but note that some competing methods were not originally designed for multimodal spatial-omics integration because tools for this setting are limited (paper.md:55-59, paper.md:363-365).

Proposed Method

ISON (Integrated Spatial Omics Network) learns shared low-dimensional representations across scRNA-seq, scATAC-seq, and spatial RNA. In the default KL-NMF model, scATAC $O$, scRNA $E$, and ST $E_s$ are decomposed as:

\[O \approx W_1H_1,\quad E \approx W_2H_1,\quad E_s \approx W_2H_2.\]

This sharing aligns scRNA and scATAC through the common cell embedding $H_1$, aligns scRNA and ST through the common gene loading matrix $W_2$, and predicts spatial ATAC by $O_s=W_1H_2$ (paper.md:121-135, paper.md:201-205). The method adds platform-effect vectors for batch correction and a spatial Laplacian term for spot-neighborhood smoothness (paper.md:139-159, paper.md:213-219). The paper also describes a contrastive joint VAE with InfoNCE and structure loss (paper.md:221-275), but the reported default ISON is KL-NMF because it outperformed the VAE on the P21/P22 benchmarks (paper.md:59-61).

Evaluation

The authors evaluate ISON on P21/P22 spatial RNA+ATAC mouse brain data, 10x Genomics Alzheimer sc-multiome and Visium datasets, simulations, low-gene-coverage experiments, regulatory-signal validation, and scalability tests (paper.md:55-87, paper.md:277-297). On P21, KL-NMF reports mean peak-wise PCC 0.23 and RMSE 1.19 versus VAE 0.09 and 1.22; on P22, KL-NMF reports PCC 0.15 and RMSE 0.83 versus VAE 0.07 and 0.84 (paper.md:59-61). With MAGIC-imputed observed ATAC, reported peak-wise PCC rises to 0.69 for P21 and 0.63 for P22 (paper.md:59-61).

The regulatory analyses show predicted ATAC preserving distance-dependent peak-gene correlations, eQTL/Hi-C enrichment, motif activity patterns, and Moran’s I spatial variability (paper.md:73-79). In the Alzheimer case study, the paper uses predicted spatial ATAC plus ST with LINGER to infer TF activity and TF-target networks, then identifies disease/age-associated modules; module 5 in L5/6 NP cells is highlighted with APP-related enrichment (paper.md:91-99).

Reproducibility

Rating: 3/5. The paper states that code is public at https://github.com/Durenlab/ISON, under MIT license, with a Zenodo archive, and uses Python 3.9 (paper.md:379-381). The acquired code snapshot contains a compact KL-NMF implementation that matches the paper’s default factorization, baseline KL scaling, platform-effect augmentation, spatial graph/Laplacian logic, and output formulas (doc_code.md).

The main limitations are important:

  • The acquired manuscript is an unedited early-access version, converted from the reference PDF by MinerU hybrid OCR; the paper itself warns that the early-access manuscript may still contain errors (paper.md:7-11).
  • The public code release matches the KL-NMF branch, but a self-contained VAE/InfoNCE/structure-loss implementation is MISSING; only a benchmark stub loads external VAE checkpoints (doc_code.md).
  • The non-notebook chromVAR/LINGER/K-means/GSEA downstream pipeline is Not found in the checked source, so the AD GRN results are paper/figure evidence rather than verified released-code behavior (doc_code.md, figure_analysis.md).
  • The main CLI has source-level reproducibility hazards: args.layout is used although the parser defines --lattice, obs_ratio is referenced without an in-file definition, and the adjacency helper’s default argument references an undefined visible lattice name (doc_code.md).

Overall, ISON’s default KL-NMF method is well specified and substantially present in the public repository, but the release is not a full end-to-end reproduction package for every model branch and downstream analysis claimed in the paper.

## Saturn 方法中文解读

### 1. 要解决什么问题

药物分子生成通常用 SMILES 字符串表示分子，并通过 oracle 评估活性、物化性质或结合能。高保真 oracle（例如分子对接或 DFT）更准确但每次调用昂贵，所以生成器必须用很少的 oracle 调用找到高奖励分子。论文的摘要把这个矛盾称为 sample-efficiency problem，并提出 Saturn（*Nature Machine Intelligence*, 2026，DOI: `10.1038/s42256-026-01200-4`）。

已有路线的不足在摘要中有两点：一是先用便宜 proxy oracle 筛选、再用高保真 oracle，无法直接高效优化后者；二是主流语言模型常用 Transformer，论文希望验证 Mamba 在分子生成中的作用。论文引用了 GEAM（Lee 等，ICML 2024）等分子优化方法作为比较背景，但本工作代码目录是 Saturn，GEAM 只作为 Part 3 的兼容 oracle/基线语境。

> 证据边界：本地 `paper.md` 是 Nature HTML 预览，只有摘要、四幅图、可用性和参考文献，没有完整 Methods、公式、补充材料或数值结果。下面明确区分论文主张、代码事实和解释。

### 2. Saturn 的核心想法

Saturn 用 Mamba 作为 SMILES 生成器，用一个冻结的 Prior 和一个可训练的 Agent 做强化学习。每轮把当前生成的高奖励分子放入 Replay Buffer；随后对这些分子的 SMILES 做随机化，保持奖励标签不变，进行额外训练。这就是代码中的 Augmented Memory。可选的 Hallucinated Memory 从 Replay Buffer 的分子交叉/突变生成新候选，再调用 oracle 评分。

### 3. 从输入到输出的计算流程

```text
JSON 配置 + Prior/Agent checkpoint + oracle
                |
                v
     Mamba 自回归采样 SMILES（batch）
                |
   RDKit 有效性/自由基检查 + 多样性过滤
                |
        oracle 计算奖励 r(x)
                |
   （可选）从满 Replay Buffer 生成 hallucinations
                |
       当前 batch loss + replay loss
                |
         Adam 更新 Agent；Prior 冻结
                |
   删除被惩罚 scaffold，随机化 SMILES
     重复 augmentation_rounds 次训练
                |
        达到 oracle budget，写出结果
```

入口 `Saturn/saturn.py:34-122` 读取配置并分派 `distribution_learning`、`goal_directed_generation` 或 `scoring`。RL 主循环在 `goal_directed_generation/reinforcement_learning.py:114-238`：采样、检查有效性、oracle 评分、可选 hallucination、Replay Buffer 更新、反向传播和 checkpoint 写出都在同一控制流中。

### 4. Mamba 与 SMILES 似然

`models/generator.py:19-57` 允许 RNN、Decoder 和 Mamba 三种架构；checkpoint 同时保存词表、tokenizer、最大序列长度和网络参数（`61-105`）。训练似然时，把 token 序列右移一位做 teacher forcing，得到每个样本的 NLL（`107-143`）。

Saturn 的 `MambaConfig` 默认 `d_model=256`、`n_layer=12`、RMSNorm、FP32 residual 和 fused add-normal（`models/mamba.py:202-215`）。`MixerModel` 依次执行 token embedding、Mamba blocks 和最终归一化（`105-199`），`MambaLMHead` 用与 embedding 共享权重的线性头产生 logits（`218-288`）。采样从 `^` token 开始，逐 token 采样，直到 stop token 或达到最大长度（`generator.py:179-231`）。

### 5. 强化学习目标（代码推导，非论文公式）

论文公式在本地 `paper.md` 中为 **Not found**。代码 `compute_loss`（`reinforcement_learning.py:240-257`）等价于：

$$
\ell_{prior}(x)=-\mathrm{NLL}_{prior}(x),\quad
\ell_{agent}(x)=-\mathrm{NLL}_{agent}(x)
$$

$$
\ell_{aug}(x)=\ell_{prior}(x)+\sigma r(x),\quad
L(x)=\big(\ell_{aug}(x)-\ell_{agent}(x)\big)^2.
$$

这里的 $x$ 是 SMILES，$r(x)$ 是经过 oracle 和多样性过滤后的奖励，$\sigma$ 是奖励缩放系数（Part 1 配置为 128.0）。Prior 参数在 `reinforcement_learning.py:45-52` 冻结，Adam 只更新 Agent（`97-99`, `259-275`）。上述符号是为了说明实现，不能冒充论文原始记号。

### 6. Replay 与 Augmented Memory

`experience_replay/replay_buffer.py:41-88` 将新 SMILES 和奖励加入 pandas 表，去重、按奖励降序排序，只保留前 `memory_size` 条并删除零奖励条目；`sample_memory` 随机取至多 `sample_size` 条。RL 先把当前/幻觉 batch 加入 buffer，再计算 replay loss（`reinforcement_learning.py:188-203`）。

Augmented Memory（`reinforcement_learning.py:205-220`）对当前 batch 和 buffer 中的 SMILES 调用 prior 驱动的随机化，奖励保持原值，再进行若干轮反向传播。Selective Memory Purge（`replay_buffer.py:90-117`）把 reward 为 0 的分子转换成 Bemis-Murcko scaffold，并删除 buffer 中同 scaffold 的条目，用来减少被多样性过滤惩罚的模式反复出现。这是代码机制的解释；论文关于 sample efficiency 的因果效果需要完整实验文本和数据才能确认。

### 7. Hallucinated Memory

当配置启用且 buffer 已满时，`reinforcement_learning.py:164-182` 调用 hallucinator，给新分子做 oracle 评估并把它们拼入训练 batch。GA 分支（`hallucinated_memory/genetic_mutator.py:39-68`）以 buffer 为父代群体，按奖励比例抽取两个父分子，做 crossover 和 mutation（默认 mutation rate 0.1），然后要求 RDKit 可解析、可清洗、可被 tokenizer/词表编码（`hallucinator.py:110-132`）。也存在 token 级 sequence mutator（`hallucinated_memory/sequence_mutator.py:14-144`）。提供的 Part 1–3 配置都把 `execute_hallucinated_memory` 设为 `false`，因此该分支是可用实现而不是这些复现实验的已启用路径。

### 8. 复现实验与评价

- Part 1：ChEMBL 33 Mamba checkpoint，batch size 16，oracle budget 1,000，Replay Buffer 100，sample size 10，十轮 augmented-memory（`experimental_reproduction/part_1/part-1-mamba-config.json`）。
- Part 2：DockStream/AutoDock Vina，对 6cm4、3kc3、1eve 做 docking；需要外部 DockStream 环境和可执行文件（`experimental_reproduction/README.md:18-23`）。
- Part 3：遵循 GEAM 的比较协议，ZINC 250k Mamba prior，oracle budget 3,000，支持 parp1、fa7、5ht1b、braf、jak2（`README.md:26-35`; `part_3/config.json`）。

## Saturn: Sample-efficient generative molecular design using memory manipulation

### Problem

Goal-directed molecular generation often relies on cheap proxy oracles because high-fidelity simulations, such as docking or density functional theory (DFT), consume too many oracle calls. The paper frames this as a sample-efficiency problem and proposes improving the generator's use of each evaluated molecule (`paper.md:9-12`).

### Proposed Method

Saturn combines a Mamba language model for autoregressive SMILES generation with experience replay and data augmentation. The implementation freezes a prior generator, updates an agent with a reward-shifted likelihood objective, retains top-reward molecules in a replay buffer, and repeatedly randomizes their SMILES representations for additional updates (`Saturn/goal_directed_generation/reinforcement_learning.py:240-275`; `Saturn/experience_replay/replay_buffer.py:41-88`). Optional hallucinated memory uses replay molecules as parents for sequence or GraphGA-style mutations, while selective scaffold purge removes diversity-filter-penalized scaffolds before augmentation (`replay_buffer.py:90-117`; `hallucinated_memory/genetic_mutator.py:39-68`).

### Evaluation

The abstract claims that Mamba intensifies the benefit of experience replay, that Saturn outperforms 16 models on multiparameter optimization, and that it can directly optimize DFT simulations (`paper.md:9-12`). Fig. 2 visually presents exploration/exploitation and augmented-memory comparisons; Fig. 3 compares reward distributions for random ZINC 250k, GEAM, and Saturn generations across five protein targets; Fig. 4 depicts DFT-oriented optimization with a 500-call oracle budget (`figure_analysis.md`).

The reproduction code exposes three experiment families: (1) ChEMBL 33 pretraining/goal-directed optimization with budget 1,000; (2) DockStream/AutoDock Vina docking against 6cm4, 3kc3 and 1eve with budget 1,000; and (3) a GEAM-protocol benchmark with a ZINC 250k Mamba prior, five supported docking targets and budget 3,000 (`Saturn/experimental_reproduction/README.md:12-35`; configs under `experimental_reproduction/`). Exact endpoint values, baseline names, and statistical tests are not present in the acquired `paper.md`.

### Reproducibility

**Rating: 3/5 (code available, source evidence incomplete).** Saturn is available at commit `4a3e10b5475617c9c9bcb846ee5467a3d531b88b`, with checkpoint models, configs and example outputs. The README gives the launch command (`source setup.sh`; `python saturn.py <config JSON>`) but requires path edits, GPU-recommended dependencies, and external DockStream/Vina installations for docking. The canonical Nature HTML acquisition is only a preview: full Methods, equations, Supplementary Section 1.6 data processing, quantitative tables, exact 16-model comparison, and DFT oracle configuration are `MISSING`. GEAM is retained as a cited baseline/compatibility oracle, not treated as Saturn's primary code.

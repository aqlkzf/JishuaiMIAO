## GEDI 2.0：把批次校正、连续差异表达和通路解释放进同一个潜变量模型

### 先抓住本文真正的贡献

GEDI 2.0 不是一个新统计模型，而是原始 GEDI 模型的高性能重实现。原模型把多样本单细胞表达分解为共享生物结构和样本特异偏移，从而同时得到整合表示、批次校正表达和无需先聚类的连续差异表达。2.0 版保持这套数学目标，主要重写了内存布局、稀疏矩阵处理、线性代数和样本级并行，使其能处理百万细胞。

本工作区核对 Bioinformatics 2026 论文 `10.1093/bioinformatics/btag334`、5 页补充图、官方代码 `csglab/gedi2` 提交 `1d87daa85a73dd4cddc7d59027cda119fd594627`，以及 benchmark 仓库提交 `0f0a33c5320deb3e9fdf1c24f7322556d08304f1`。

### 1. 模型怎样描述每个细胞

设第 $i$ 个样本的第 $n$ 个细胞在 $K$ 维潜空间中的坐标为 $b_n$。$Z=[z_1,\ldots,z_K]$ 是所有样本共享的基因方向，$\Delta Z_i$ 是样本 $i$ 对这些方向的特异扭曲。忽略便于阅读的尺度矩阵和偏置后，表达均值的核心可写为：

$$
\hat y_{in}\approx (Z+\Delta Z_i)b_n+o+o_i+s_{in}.
$$

其中 $o$ 是共享基因偏置，$o_i$ 是样本特异基因偏置，$s_{in}$ 表示细胞/文库大小项。论文把 $Zb_n$ 解释为去除样本偏移后的表达空间值，把 $\Delta Z_i b_n$ 解释为样本 $i$ 相对共享参考的表达扭曲。

这一区分解释了 GEDI 的三种输出：

- 用 $b_n$ 或 $Zb_n$ 比较跨样本细胞状态，实现整合与批次校正；
- 比较不同条件下的 $\Delta Z_i b_n$，在连续细胞状态上计算差异向量场，无需先把细胞切成 cluster；
- 若给出基因—通路矩阵 $C$，可令共享方向 $Z$ 受通路权重约束；若给出样本协变量矩阵 $H$，可令 $\Delta Z_i$ 受疾病、处理等样本变量解释。

“clustering-free”不是说完全不需要样本标签或先验，而是差异表达不要求先划定离散细胞群。结果仍依赖样本设计矩阵、潜因子数、输入特征以及模型收敛。

### 2. 训练的三个阶段

论文把计算过程概括为：模型 setup、潜变量初始化、迭代 block coordinate descent。

#### 2.1 Setup

R6 接口 `CreateGEDIObject()` / `$setup()` 接受样本标签与一种观测：原始计数 `M`、成对计数、连续表达 `Y` 或二元数据 `X`，并准备基因/细胞索引、样本切分、先验矩阵和超参数。`R/gedi_class.R:76-390` 是数据准备主路径。

原始计数在 C++ 中按样本转换成 `log1p` 表达；成对计数转换为对数比。需要注意，代码不是“从头到尾所有对象都保持稀疏”：输入计数与若干归一化运算使用 Eigen sparse，但拟合目标 `target_Yi` 最终是 dense matrix（`src/gedi_core.cpp:287-375`）。因此论文的“strict sparse-matrix preservation”更准确地理解为避免不必要的上游稠密副本，而不是核心优化完全不产生稠密矩阵。

#### 2.2 初始化

R 层生成 randomized SVD 所需对象，C++ core 初始化共享 $Z$、样本偏移 $Q_i$、细胞坐标 $B_i$、尺度 $D$ 和偏置。公开入口 `GEDI_initialize()` 与一体化训练入口在 `gedi_core.cpp:1686-1800`。初始化仍会受到随机种子、rSVD 过采样和底层 QR/SVD 实现影响。

#### 2.3 块坐标下降

训练不是反向传播，而是在固定其余参数时交替求解一组线性代数子问题。例如 `solve_Bi_all()` 为每个样本构造 $(Z+Q_i)\operatorname{diag}(D)$，用 LDLT 解细胞潜坐标；`solve_Z_*()` 聚合各样本残差并更新共享方向；随后更新样本偏移、偏置、先验映射和方差超参数。

这类更新的关键性质是：给定全局参数后，各样本的 $B_i$、$Q_i$ 等可独立计算。源码 `gedi_core.cpp:879-898` 和其他更新函数以 OpenMP `parallel for` 并行样本循环；全局 $Z$ 等更新仍需汇总同步，所以线程数增加到 16 以后收益递减。

### 3. 2.0 为什么更省内存、更快

#### 单一 C++ 状态所有权

GEDI 2.0 用 R6 对象保存一个外部 C++ 指针，参数、辅助量和工作区主要常驻 C++。`gedi_core.cpp:77-166` 明确列出 `params_*`、`aux_*` 与预分配 `workspace_*`。优化过程中原位更新，避免旧实现每轮在 R 与 C++ 之间复制整套参数。

#### 预分配和按需计算

`workspace_Y_res`、`workspace_B_concat`、`workspace_ZD` 等在对象生命周期中复用。代码只保存一次 $DB_i$，而 $ZDB_i$、$Q_iDB_i$ 在需要时计算（`gedi_core.cpp:938-1000`）。最终 `wrap_results()` 明确不把巨大的 target 数据复制回 R（`gedi_core.cpp:1462-1468`）。

#### 稀疏输入和 Eigen/BLAS

`matrix_oprations.cpp` 对计数归一化等操作使用稀疏矩阵迭代与 sparse-dense 乘法；核心求解使用 Eigen 的 LDLT、SVD 和矩阵块操作。这降低了临时对象和解释器调用开销，但部分模型目标仍按样本稠密保存，所以百万细胞实验仍需要约 106 GB，而不是普通笔记本规模。

#### OpenMP 样本并行

并行粒度主要是样本，而不是任意矩阵元素。样本数少或单个样本极大时，OpenMP 加速上限会与论文的多样本 benchmark 不同；编译器未启用 OpenMP 时，`num_threads` 也不能产生同样加速。

### 5. 代码与论文的对应及边界

- **Exact**：C++ 常驻状态与预分配 workspace，可在 `gedi_core.cpp:77-166` 直接确认。
- **Exact**：样本级 OpenMP 并行，可在 `solve_Bi_all()` 等函数看到。
- **Exact**：稀疏计数归一化与 Eigen sparse 操作，可在 `matrix_oprations.cpp` 确认。
- **Exact**：benchmark 仓库分别用相同参数训练 legacy 和 new model，并提供 panel B/C/E/F 脚本。
- **Partial**：论文摘要说提供 R 和 Python interfaces；固定代码快照是标准 R package，仓库中没有独立 Python package。README 的 Python 用法主要通过环境互操作或当前文档边界，不能据此声称原生 Python API 与 R API 同等完整。
- **Partial**：“full numerical equivalence”应限定为作者的匹配参数 benchmark；主结果相关系数并非 1，只有换用同一 LAPACK QR 后才达到机器精度。
- **Not run**：本工作区没有下载大型 Allen Brain/Seurat benchmark 数据，也没有重跑百万细胞测试。

### 6. 一个实际使用流程

1. 准备 features × cells 的计数矩阵和每个细胞的 sample ID；不同样本必须共享特征。
2. 选择潜因子数 $K$，可选提供基因先验 $C$ 和样本设计 $H$。
3. `CreateGEDIObject(...)` 完成 setup，再 `$initialize_lvs()` 与 `$optimize()`，或使用一体化训练接口。
4. 从 `model$projections` 获取共享/样本特异表示；用 `diffExp()` 或 dynamics 接口针对样本条件 contrast 计算连续差异。
5. 保存代码提交、GEDI 参数、特征筛选、随机种子、线程数、BLAS/Eigen 和编译环境；跨平台只期待统计等价，不期待逐 bit 等价。

### 7. 最终理解

GEDI 的科学价值来自“共享参考轴 $Z$ + 样本特异扭曲 $\Delta Z_i$”这一分解；GEDI 2.0 的贡献来自让同一分解在 atlas 规模上可计算。它没有通过近似小模型换速度，而是通过状态所有权、预分配、稀疏输入、优化线性代数和样本并行减少冗余。与此同时，“百万细胞可行”仍指约 106 GB HPC 资源；“full equivalence”也必须附带相同算法参数和数值库的条件。

## GEDI 2.0 Summary

GEDI 2.0 makes the original GEDI unified single-cell model practical at atlas scale. GEDI decomposes expression into shared biological axes and sample-specific distortions, enabling integration, batch-corrected expression, continuous clustering-free differential expression, and optional pathway/regulatory interpretation in one fitted model.

The 2.0 contribution is computational: a standalone C++ core owns model state, reuses preallocated workspaces, preserves sparse count representations where possible, uses Eigen/BLAS linear algebra, and parallelizes independent per-sample block-coordinate updates with OpenMP.

### Main evidence

- Shared corrected expression and sample-specific distortions correlate 0.9887 and 0.9922 between legacy and 2.0 implementations.
- Matching the QR implementation reduces remaining discrepancies below $10^{-14}$ in the supplementary analysis.
- Peak memory falls 45%–67% across the reported grid, with median 66%.
- Mean multithread speedup is 6.08× and maximum 11.5× at 32 threads; scaling becomes less efficient beyond 8–16 threads.
- A one-million-cell, 2000-feature run completed in about two hours using 16 threads and roughly 106 GB; legacy GEDI exceeded 200 GB.

### Reproducibility

Official source and benchmark scripts are public and pinned locally. The implementation path and paper claims are auditable, but large benchmark datasets were not fetched and the million-cell experiment was not rerun. Reproduction depends on OpenMP, Eigen/BLAS/QR implementation, random initialization, feature selection, iteration count, and hardware. The source snapshot is an R package backed by Rcpp/Eigen; a separate native Python package was not found.

**Assessment: 4/5 for auditability, 3/5 for full numerical rerun.**

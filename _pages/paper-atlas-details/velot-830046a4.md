## VelOT 方法中文解读

### 1. 这篇论文解决什么问题？

VelOT 解决的是单细胞 RNA velocity 的一个核心痛点：很多数据集没有可靠的 spliced/unspliced 读数，或者不满足传统动力学模型的稳态、恒定速率、准确内含子注释等假设。scVelo、DeepVelo、UniTVelo、MultiVelo、veloVI 等方法虽然复杂程度不同，但仍然围绕转录、剪接、降解的动力学模型展开；论文认为这些假设在疾病样本、低覆盖样本、扰动样本、成熟组织或稀有细胞群中容易失效（`paper.md:18-24`）。

VelOT 的核心转向是：不再问“每个基因的剪接动力学参数是什么”，而是问“在表达流形上，较早的细胞分布应该怎样局部搬运到较晚的细胞分布”。因此，VelOT 把 RNA velocity 写成一个高维表达空间里的几何和最优传输问题（`paper.md:27-53`, `paper.md:149-155`）。

### 2. 为什么已有方法不够？

论文指出传统 kinetic RNA velocity 有三类约束：

- 需要可靠的 unspliced/spliced 计数，而这些读数受测序深度、内含子注释、ambient RNA 和预处理流程影响很大。
- 许多模型默认细胞类型内剪接/降解速率稳定，且系统接近稳态；这在发育、扰动、肿瘤和疾病样本中不一定成立。
- kinetic 模型常常同时估计 latent time 和 velocity，时间轴会反过来依赖 velocity 拟合，产生循环依赖（`paper.md:18-24`）。

VelOT 用 Diffusion Pseudotime 先独立建立时间轴，再用 OT 估计局部位移。这样 velocity 不再参与 pseudotime 的生成，从机制上避免了 latent-time/velocity 的循环拟合。

### 3. VelOT 的主要创新

VelOT 可以概括为三点：

1. **动力学无关的时间锚定**：用 kNN 图上的 diffusion pseudotime 表示细胞从 root 到 terminal 的进程，而不是用 velocity 模型自己学 latent time（`paper.md:70`, `paper.md:191-194`; `velot/velot/pp.py:154-203`）。
2. **局部窗口最优传输**：先在 PCA 空间做空间分区，再在每个分区内按 pseudotime 切成时间窗口，只在相邻窗口间求 OT，避免跨分支、跨远距离的错误搬运（`paper.md:197-209`; `velot/velot/tl.py:54-403`）。
3. **神经网络平滑成连续速度场**：OT 得到的是离散细胞上的 raw velocity，VelOT 再用一个小 MLP 学习连续的 velocity field，并用局部平滑、curl/divergence 等约束减少噪声和不合理流线（`paper.md:215-224`; `velot/velot/tl.py:425-734`）。

论文还提出 VelOT-MetaFlow，用 VAMPFlow 思路把连续速度场粗粒化成 meta-state、转移矩阵、source/sink/branch/cycle 状态和 committor probability（`paper.md:129-142`, `paper.md:233-248`）。但在当前代码快照中，MetaFlow 主要在 `notebooks/vamp/velot_metaflow_with_velot_velocity.py`，不是 `velot/velot/` 里的正式包级 API。

### 4. 计算流程

```text
原始 count matrix
  -> normalize_total / log1p / HVG / scale
  -> PCA 得到 X_PCA
  -> kNN 图 + Diffusion Pseudotime tau
  -> PCA 空间聚类或使用已有 cell type 分组
  -> 每个分组内部按 tau 排序，生成时间窗口
  -> 相邻窗口之间求 entropy-regularized OT
  -> 每个 source cell 的 expected displacement = raw velocity
  -> 用窗口覆盖次数得到 confidence
  -> MLP f_theta(x, tau) 学习连续速度场
  -> 局部线性 Jacobian 把 PCA velocity 投影到 UMAP 作图
  -> 可选：MetaFlow/VAMP notebook 做 meta-state 粗粒化
```

#### Step 1: 预处理和 pseudotime

论文方法部分说从 total mRNA count 开始，做 total-count normalization、log(1+x)、HVG、scale、PCA、kNN，然后用 root cell/root group 计算 DPT（`paper.md:188-194`）。代码中对应的是 `velot.pp.prepare()`，它串联 `normalize()`、`select_genes()`、`scale()`、`pca()`、`neighbors()`、`umap()`、`pseudotime()`，并把参数写入 `adata.uns["velot_params"]`（`velot/velot/pp.py:37-295`）。

注意一个代码-论文差异：论文写 kNN 默认 `k=15`，但包里的 `prepare()` 默认 `n_neighbors=30`（`paper.md:191-194`; `velot/velot/pp.py:211-216`）。复现实验时应显式传参，而不是盲用包默认值。

#### Step 2: 空间-时间窗口

VelOT 不直接按全局 pseudotime 切片，因为复杂分支结构中，不同命运的细胞可能在 UMAP 或 PCA 局部相邻。如果全局搬运，很容易把不同命运之间错误连接起来。代码里的 `build_windows()` 会：

- 在 PCA 或指定 `basis` 中做 K-Means，或使用 `spatial_key` 提供的分组；
- 每个空间分组内按 `pseudotime` 排序；
- 生成重叠 temporal windows；
- 把相邻 windows 配成 source/target OT pairs；
- 将结果存到 `adata.uns["velot_windows"]`（`velot/velot/tl.py:54-234`）。

论文写窗口默认 `W=80`、overlap `0.1`；包默认 overlap 是 `0.5`，而代表性 benchmark 脚本常设成 `0`（`paper.md:197-200`; `velot/velot/tl.py:54-65`; `velot/article/benchmark/real/pancreas_velot.py:43-55`）。这是另一个需要显式记录的 default drift。

#### Step 3: OT velocity

对每对 source/target window，VelOT 求一个带熵正则的 OT plan。代价矩阵包含三项：

```text
C_ij =
  normalized squared distance in PCA
  + lambda_time * 1[tau_i > tau_j]
  + lambda_knn * 1[j not in KNN(i)]
```

这表示：距离远的搬运更贵，向时间倒退的搬运更贵，跨出局部流形邻域的搬运更贵（`paper.md:203-209`）。代码 `_ot_velocity_pair()` 直接实现了这三项，并用 POT 的 Sinkhorn 求解；如果 Sinkhorn 失败，会 fallback 到 exact OT，再失败则返回零向量（`velot/velot/tl.py:242-295`）。

每个 source cell 的 raw velocity 是 row-normalized transport plan 下的期望位移：

```text
v_i^OT = sum_j P_hat_ij * (x_j - x_i)
```

代码对应 `(P @ X2) / row_sums - X1`（`velot/velot/tl.py:301-305`）。如果一个 cell 在多个窗口中作为 source 出现，就对多个贡献求平均，并用贡献次数归一化为 confidence（`velot/velot/tl.py:371-397`）。

#### Step 4: MLP 平滑

raw OT velocity 是离散的、局部可能有噪声，而且 terminal cells 可能没有作为 source 出现。VelOT 用一个小 MLP：

```text
f_theta([x_i, tau_i]) -> v_i
```

输入是 PCA 坐标加 pseudotime，输出是 PCA velocity。代码中的 `_VelocityNet` 是两层隐藏层加 SiLU 激活（`velot/velot/tl.py:425-444`）。

训练损失包含：

- confidence-weighted regression：只在有 raw OT velocity 的地方拟合目标；
- kNN smoothness：邻近细胞的预测 velocity 应相似；
- optional curl penalty：减少旋转成分；
- optional divergence penalty：控制局部体积变化（`velot/velot/tl.py:605-678`）。

这一步的一个重要作用是：`confidence=0` 的细胞不会贡献 regression loss，但训练后的网络仍会为它们输出速度，相当于从局部邻域插值（`velot/velot/tl.py:605-610`, `:701-713`）。

#### Step 5: 投影到 UMAP

论文强调 velocity 是在 PCA 空间估计的，UMAP 只用于可视化（`paper.md:227-230`）。代码中 `project_to_umap()` 对每个细胞在 PCA 空间找邻居，拟合局部线性映射 `dX @ A ~= dU`，再用 `V_pca @ A` 得到 UMAP velocity（`velot/velot/tl.py:817-950`）。

因此，图中的 UMAP streamlines 应理解为 PCA velocity field 的可视化投影，不是直接在二维 UMAP 上学习出的速度。

### 5. MetaFlow/VAMP 粗粒化

VelOT-MetaFlow 的目标是把连续 velocity field 变成可解释的细胞状态景观：哪些状态是 source，哪些是 terminal/sink，哪些是 branching/saddle，是否有 cycling/recurrent 结构，以及不同 terminal fate 的 committor probability。

当前代码中，MetaFlow 的关键实现位于 notebook 脚本：

- `VelOTMetaFlowConfig` 定义 latent/embedding key、VelOT velocity key、OT-flow 参数、VAMP meta-state 参数和输出目录（`velot_metaflow_with_velot_velocity.py:64-146`）。
- `vamp2_score()`、`balance_loss()`、`sharpness_loss()`、`orthogonality_loss()` 和 `train_metastate_model()` 实现 VAMP2 及正则项（`velot_metaflow_with_velot_velocity.py:777-868`）。
- `auto_select_k()` 可在 `[5,6,7,8,9,10,12]` 中选 K（`velot_metaflow_with_velot_velocity.py:900-932`）。
- `classify_metastates()` 和 `compute_terminal_committors()` 生成状态标签和 committor（`velot_metaflow_with_velot_velocity.py:1006-1111`）。
- 主函数 `run_velot_metaflow_with_velot_velocity()` 组织完整流程并写出图和 AnnData 结果（`velot_metaflow_with_velot_velocity.py:1539-1726`）。

必须注意：论文说完整数学规范在 Supplementary Methods Sec. S2（`paper.md:233-236`），但本 workspace 没有 supplementary markdown。因此 VAMP 的完整公式级说明在这里应标为 MISSING；我们只能验证 notebook 里的实现行为。

### 8. 适合怎么用？

VelOT 最适合这些场景：

- 没有可靠 spliced/unspliced count；
- 数据不满足 steady-state 或 kinetic rate 稳定假设；
- 发育/疾病/肿瘤样本里存在复杂分支；
- 希望从 total-count scRNA-seq 直接得到几何意义上的 velocity field；
- 希望把 velocity field 进一步粗粒化成状态图和 fate probabilities。

论文也提醒：VelOT 依赖 root cell/root group，root 错了可能整体翻转 velocity；它假设主要过程是 forward progression，不一定适合纯去分化；单细胞 snapshot 方法也无法解析短于采样间隔的真实动态（`paper.md:167-170`）。

## VelOT Summary

### What Problem The Paper Solves

VelOT addresses RNA velocity inference when spliced/unspliced quantification or kinetic assumptions are unreliable. Classical RNA velocity methods such as scVelo, DeepVelo, UniTVelo, MultiVelo, and veloVI fit or relax kinetic models of transcription, splicing, and degradation; the paper argues these methods still depend on assumptions about steady state, rate stability, intronic-read quality, and latent-time self-consistency (`paper.md:18-24`).

VelOT replaces that kinetic framing with a geometry and transport framing. It treats cells as samples on a high-dimensional expression manifold, anchors time using diffusion pseudotime, estimates local movement by optimal transport from earlier to later windows, and smooths those discrete displacements into a continuous vector field (`paper.md:27-53`, `paper.md:59-78`).

### Proposed Method

The core method has four stages:

1. Preprocess raw counts into a PCA representation and compute a kNN graph, UMAP, and diffusion pseudotime independent of velocity (`paper.md:70`, `paper.md:188-194`; `velot/velot/pp.py:37-295`).
2. Partition cells into spatial clusters in PCA space, sort each cluster by pseudotime, and form local temporal window pairs (`paper.md:197-200`; `velot/velot/tl.py:54-234`).
3. Solve entropy-regularized OT for each window pair with a cost that penalizes expression distance, backward pseudotime, and non-neighbor transport, then convert each plan into expected-displacement raw velocity (`paper.md:203-209`; `velot/velot/tl.py:242-403`).
4. Train a lightweight MLP velocity field with confidence-weighted regression, kNN smoothness, and optional curl/divergence penalties, then project PCA-space velocity to UMAP for visualization (`paper.md:215-230`; `velot/velot/tl.py:425-950`).

The paper also introduces VelOT-MetaFlow, a downstream VAMP-style coarse-graining workflow that learns soft meta-states, transition matrices, state labels, committors, and PAGA-like directed graphs (`paper.md:129-142`, `paper.md:233-248`). In the code snapshot, this is implemented primarily as a notebook workflow rather than as a package-level `velot` API (`velot/notebooks/vamp/velot_metaflow_with_velot_velocity.py:64-1726`).

### Main Results

The paper evaluates VelOT on pancreas endocrinogenesis, a synthetic helicoidal trajectory, erythroid maturation, a benchmark suite of real and synthetic datasets, MetaFlow pancreas coarse-graining, and an oligodendroglioma application (`paper.md:79-146`).

Image-grounded evidence from local figures:

- Fig. 1 shows the complete pipeline from raw counts through DPT, OT windows, raw velocity, MLP smoothing, and UMAP streamlines.
- Fig. 2 shows pancreas streamlines branching from progenitor/intermediate cells to alpha, beta, delta, and epsilon endocrine endpoints, with high ICCoh and CBDir panels.
- Fig. 3 shows a long curved synthetic trajectory where raw/smoothed velocities and streamlines follow the curve rather than jumping across arms.
- Fig. 4 shows unidirectional erythroid maturation from blood progenitors to terminal erythroid cells.
- Fig. 5 shows VelOT ranked first in the displayed real and synthetic benchmark matrices.
- Fig. 6 shows 12 pancreas MetaFlow meta-states, a directed coarse graph, enrichment dots, and an alluvial cell-type mapping.

The benchmark section reports that VelOT outperforms scVelo stochastic, scVelo dynamical, DeepVelo, and FluxMatching on CBDir/ICCoh and remains computationally efficient (`paper.md:115-124`). Local code supports the metric definitions and per-dataset scripts, but this analysis did not rerun the benchmark (`velot/velot/metrics.py:69-371`; `velot/article/benchmark/real/pancreas_velot.py:1-84`).

### Reproducibility And Code-Paper Match

Reproducibility rating: **3/5**.

Strengths:

- Core VelOT package is present and directly maps to the paper's main pipeline.
- Code includes preprocessing, windowing, OT velocity, smoothing, projection, metrics, plotting, benchmark helpers, dataset scripts, figure assets, and VAMP notebook workflow.
- Repository provenance is captured: `https://github.com/lucas-rdlr/velot` at commit `5601a5a0f0a874a6d7359d3f6d03c0587d47f51e`.

Limitations:

- `SUPP_MD=none`; the complete VAMP mathematical specification and some robustness/ablation details cannot be verified from supplementary text.
- MetaFlow/VAMP is notebook-centric under `notebooks/vamp/`, not a clean package-level module.
- Paper-code defaults drift for kNN, window overlap, and curl settings; paper/figure-level parameters should be passed explicitly.
- The paper says hyperparameters are stored as YAML files, but no local YAML hyperparameter configs were found besides `.readthedocs.yml`.
- Benchmark scripts exist, but shell runners are host-specific and commented rather than one-command reproducibility drivers.
- Zenodo data bundle, pretrained MetaFlow weights, and parsed supplementary tables were not acquired into this workspace.

Overall code-paper fidelity is **medium**. The main VelOT method is well supported by direct code lines; the downstream MetaFlow and some paper-wide reproducibility claims require external supplementary/Zenodo materials.

### Key Limitations From The Paper

The authors state that VelOT requires a root cell or root group, and root mis-specification can flip the velocity field globally. The method assumes a predominantly forward process and may not capture pure de-differentiation. Like other single-cell trajectory methods, it cannot recover dynamics faster than the sampling interval. The smoothness regularizer also introduces a hyperparameter that may need tuning to the data manifold (`paper.md:167-170`).

### Best Use Cases

VelOT is most appropriate when spliced/unspliced counts are unavailable or unreliable, the system is far from steady state, rare populations make kinetic fitting fragile, or the goal is a geometry-first velocity field from total-count scRNA-seq. It is complementary to kinetic velocity: agreement strengthens confidence, while disagreement can flag kinetic-assumption failure or embedding/pseudotime sensitivity (`paper.md:161-170`).

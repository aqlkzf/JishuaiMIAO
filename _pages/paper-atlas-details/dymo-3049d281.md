## DyMo 方法中文解读

### 一句话理解

DyMo 处理的是不完整多模态分类中的一个两难：缺失模态经过生成模型恢复后，全部丢弃会浪费有用信息，全部纳入又可能把恢复误差带进分类器。它不再把“是否相信恢复结果”设成全局固定规则，而是在每个样本的推理过程中，逐个估计候选恢复模态能否提高当前表示的任务相关质量，只保留正收益模态。

### 问题设定与核心直觉

设一个样本共有 $M$ 个模态，掩码 $m_j=1$ 表示第 $j$ 个模态缺失。恢复器先产生所有缺失模态的候选值，但这些候选并不自动等同于可靠观测。DyMo 把当前已采用的模态集合记为 $S$，对一个尚未采用的恢复模态 $u$，比较加入前后的表示质量：

$$
R_u = Q(S\cup\{u\})\,G_u-Q(S).
$$

$Q$ 是由分类特征与类别原型得到的任务质量分数，$G_u$ 是根据类内相似度统计得到的校准系数。若 $R_u>0$，候选模态可能带来任务相关信息；若 $R_u\le 0$，它在当前样本和当前集合下没有帮助，甚至可能有害。

这一定义强调的是“对当前分类任务有没有增益”，不是恢复信号在像素或输入空间是否逼真。因此，同一个恢复器生成的两个模态可以得到完全不同的选择结果，不同样本也可以走不同的选择路径。

### 可处理任意缺失组合的分类器

论文和代码使用 DynamicTransformer 作为下游分类器。每个模态先由自己的编码器转成 token，再加入模态嵌入；缺失模态 token 被置零，并在注意力掩码中赋予大负值，使 Transformer 不关注这些位置。一个可学习的 `[CLS]` token 汇聚当前可见模态，经过分类头得到预测，同时经过投影层得到用于原型距离计算的低维特征。

代码在 `DynamicTransformer.py:101-113` 枚举所有非空模态子集并建立掩码到子集编号的映射；`116-166` 完成带掩码的训练前向，`128-153` 同时实现零 token 和注意力屏蔽。这使同一个分类器能够评估“加入候选模态前”和“加入后”两种集合，而不必为每种缺失模式训练独立模型。

### 任务质量、类别原型与 ICS 校准

分类特征与各类别原型比较后形成类别分数。余弦版本使用归一化特征与原型的相似度，欧氏版本使用负平方距离；softmax 后的最大值作为当前表示的质量代理。这里选择的是模型预测类别，而不是测试标签，所以推理时不需要真实标签。

仅比较原型质量仍可能误判：某些类别天然分布更松散，同样大小的距离变化在不同类别或不同模态子集下含义不同。DyMo 因而离线统计每个模态子集、每个类别的原型和距离标准差，用截断高斯分布的概率刻画类内相似度（ICS），再以加入候选前后的 ICS 变化构造 $G_u$。代码入口位于 `quality_prototype.py:63-118`；`DyMo.py:85-117` 读取总体原型和子集高斯统计，分别计算加入前后质量与校准概率。

实现细节需要与论文抽象区分：余弦路径在校准概率下降时采用对数比，欧氏路径采用概率比；最终实现是 `quality_u * G - quality`。这是一种可运行的任务损失代理，并非直接估计互信息，也不是逐样本计算论文理论式中的真实条件分布。

### 推理期逐步选择

对每个样本，实际流程如下：

1. 冻结恢复器并一次性生成所有缺失模态候选。
2. 以原始观测模态为初始集合，分别尝试解除每个候选模态的掩码。
3. 计算每个候选的校准收益 $R_u$。
4. 将负收益候选标为不再考虑；在剩余候选中加入收益最大的一个。
5. 更新当前掩码并重复，直到没有正收益候选或所有缺失模态都已处理。
6. 用最终选择出的模态集合运行分类器，得到预测。

`DyMo.py:123-171` 对应这一贪心循环。选择是条件性的：一个模态的收益会随已纳入集合改变，所以不能只在开始时为所有候选排序一次。算法保存奖励、掩码和动作历史，便于分析每个样本的选择轨迹。

虽然 `forward` 和 `calculate_reward` 的接口接收 `y`，当前奖励计算没有使用真实标签；预测类别来自模型输出。这一点很重要：代码不是借助测试标签进行选择，但多余的接口参数容易让阅读者误解。

### 训练阶段为何要模拟缺失

推理时需要分类器在许多模态子集上都产生可比较的特征，因此训练不能只看完整样本。论文对每个批次随机采样多个模态子集，以各子集上的分类损失训练模型，并加入原型对比辅助损失，使同一类别在不同缺失模式下的投影特征靠近类别原型、不同类别分离。

代码中的整体训练目标可概括为

$$
\mathcal L=\mathcal L_{\mathrm{class}}+\lambda\mathcal L_{\mathrm{aux}}.
$$

`DownstreamAugmentationExperiment.py:167-200` 实现随机子集训练和两项损失组合，`237-239` 更新类别原型。训练后的特征空间既服务分类，也为推理期的质量比较提供共同坐标系。

### 从训练到测试的三段式实现

仓库实际复现不是一个单命令端到端流程，而是三段式：先训练能处理任意掩码的 DynamicTransformer；再通过 `gaussian_COS.ipynb` 或 `gaussian_EU.ipynb` 离线生成每个子集的原型和距离统计；最后加载预训练 Transformer、冻结的 MoPoE 或 SimpleImputer 以及 `subset_gaussian*.pt`，运行 DyMo 测试。

这意味着高斯统计文件是必需的中间产物，但生成过程仍位于 notebook，没有完全纳入训练脚本。代码环境文件记录 Python 3.9.15、PyTorch 1.11 和 CUDA 11.3；本地 `code/` 是源码快照，未保存可核验的 Git commit，因此不能宣称与某个上游提交逐字一致。

### 实验和图表应怎样读

论文覆盖 PolyMNIST、MST、CelebA、DVM 和两个 UK Biobank 分类任务，模态从多视图图像扩展到图像、文本和表格组合。实验的关键比较不是单纯“恢复器谁更好”，而是同一恢复结果在丢弃、全部使用和 DyMo 动态选择下的分类差异。论文还搭配多种恢复方法，意在说明选择层可以叠加到不同恢复器之上。

阅读图表时可以沿三条证据链理解：概念图先展示丢弃与盲目补全的两难；方法图展示恢复、奖励评估和逐步选择；定量表格与案例图再检验动态路径是否能避免有害恢复并保留有用恢复。详细图号、子图内容和数值证据见 `figure_analysis.md`，完整公式推导见 `doc_method.md`。

### 方法边界与代价

- 当前实现面向有监督分类，奖励依赖类别原型和分类特征；不能直接宣称适用于回归、生成或开放集任务。
- 每次迭代要为多个候选分别做加入前后评估，会产生多次分类器前向；缺失模态越多，推理开销越大。
- 代码枚举非空模态子集，并为子集准备统计量，规模随模态数呈指数增长；在少量模态数据上可行，但不是高模态数场景的现成解法。
- 收益可靠性受恢复器、分类器校准、原型质量和训练/测试分布漂移共同影响。错误恢复若仍使模型过度自信，也可能被选中。
- “即插即用”指推理选择层不再训练额外参数，并不表示无需预训练分类器、恢复器或离线统计。
- UK Biobank 数据受访问限制；仓库代码和公开数据集可以核验方法路径，但不能据此保证所有医学实验可无条件复现。

### 最终理解

DyMo 的贡献不是提出另一种补全网络，而是把补全后的决策从固定规则改成样本级、条件式的任务收益选择。它依赖一个能处理任意缺失组合的分类器、一个跨子集可比较的原型特征空间，以及离线类内统计来校准贪心奖励。最适合把它理解为恢复器与下游分类器之间的推理控制层：恢复器提供候选，DyMo 决定哪些候选值得进入最终预测。

## DyMo: Inference-Time Dynamic Modality Selection for Incomplete Multimodal Classification

### Motivation & Novelty

#### Problem
Multimodal deep learning requires all modalities at inference, but real-world data frequently has missing modalities (sensor failures, different clinical protocols, transmission errors). Existing approaches face the **discarding-imputation dilemma**: recovery-free methods (discarding) lose task-relevant information when informative modalities are absent, while recovery-based methods (imputation) risk injecting noise from low-fidelity or semantically misaligned reconstructions.

#### Limitations of Existing Approaches
- **Recovery-based** (MoPoE, ICLR 2021; M3Care, KDD 2022; OnlineMAE, AAAI 2023): generate all missing modalities without assessing quality, blindly integrating unreliable reconstructions that can degrade predictions
- **Recovery-free** (ModDrop, IEEE TPAMI 2015; MTL, CVPR 2022; MAP, CVPR 2023; MUSE, ICLR 2024): ignore missing modalities entirely, suffering large performance drops when highly task-relevant modalities are absent (e.g., MUSE drops 61.18% accuracy on MST when missing {M,T} vs {S,T})
- **Dynamic fusion** (QMF, ICML 2023; DynMM, CVPRW 2023; PDF, ICML 2024): weight modalities by reliability but assume all modalities available, and cannot detect semantically misaligned recoveries

#### Unique Contributions
1. **First** to identify and address the discarding-imputation dilemma with dynamic neural networks
2. **MTIR reward**: theoretically grounded in mutual information, connects task-relevant information gain to classification loss decrease via Hoeffding's inequality, with intra-class similarity calibration (ICS) for robustness
3. **Inference-time algorithm**: no additional parameters or architecture overhead — operates on the existing network's representation space, making it plug-and-play with any recovery method
4. **Flexible architecture**: multimodal transformer with attention masking handles arbitrary modality subsets; incomplete simulation training ensures robust features across all missing patterns

---

### Method Overview

DyMo has three components:

1. **Multimodal Architecture**: modality-specific encoders + multimodal transformer with [CLS] token classification. Attention masks prevent missing modality dummy tokens from corrupting representations.

2. **Dynamic Selection Algorithm (inference only)**: for each test sample, recovers all missing modalities, then iteratively evaluates each recovered modality's contribution via the MTIR reward (calibrated information gain proxy). Adds the most beneficial modality per step; permanently removes harmful ones (R ≤ 0). Terminates when no positive-reward candidates remain.

3. **Training Strategy**: randomly samples $A$ modality subsets per batch for classification loss, plus a prototype-based contrastive loss to enforce intra-class clustering regardless of missing patterns. Prototypes updated as running means per epoch.

The inference algorithm requires precomputed Gaussian parameters (per-subset prototypes and distance standard deviations) generated offline after training.

See `doc_method.md` for full mathematical derivations and algorithm walkthrough. See `doc_code.md` for code-paper mapping.

#### Key Results

**vs. Static/Dynamic Fusion** (same recovered modalities given to all methods):
- PolyMNIST (80% missing): DyMo_e **96.81%** vs best prior 84.21% (CONCAT) — **+12.60%**
- DVM (full table missing): DyMo_e **93.36%** vs 88.36% (CONCAT) — **+5.00%**
- CelebA (missing text): DyMo_c **95.20%** vs 86.67% (CONCAT/PDF) — **+8.53%**

**vs. Incomplete MDL SOTAs** (both recovery-based and recovery-free):
- PolyMNIST (80% missing): DyMo_e **96.81%** vs 91.14% (MTL, recovery-free) — **+5.67%**
- MST (missing {M,T}): DyMo_e **86.84%** vs 85.16% (M3Care†) — **+1.68%**
- Infarction (70% missing table): DyMo_e **76.14%** vs 75.73% (MTL) — **+0.41%**

**Ablation study** confirms each component contributes: MTIR reward > iterative selection > ICS calibration. Average 1.38 selection iterations on PolyMNIST with 80% missing — moderate overhead.

**Robustness**: DyMo works with different recovery methods (MoPoE, MMVAE+, CMVAE) and degrades gracefully under extreme noise conditions (controlled correct recovery rate experiments).

### Reproducibility

**Rating: 4/5** (High)

**Strengths**:
- Complete code released with all 13 baselines and 5 datasets
- Hydra-based configuration makes experiments reproducible
- Clear 3-stage pipeline: (1) train DynamicTransformer, (2) generate Gaussian params, (3) run DyMo test
- Single NVIDIA A5000 GPU sufficient

**Weaknesses**:
- Gaussian parameter generation via Jupyter notebooks (not integrated into pipeline)
- UK Biobank data requires approved access (Application 40616)
- MoPoE/TIP pre-trained checkpoints referenced by absolute paths (need retraining or checkpoint sharing)
- Some implementation choices differ from paper (α for cosine distance, reward in probability space)

**Practical Notes**:
- Dependencies: Python 3.9.15, PyTorch 1.11.0, CUDA 11.3.1
- Training: early stopping with patience=20, epochs up to 300 for DVM/UKBB
- The `pt_rate` hyperparameter controls auxiliary loss weight (not mentioned in paper)
- Prototype loss disabled during first 3 epochs (undocumented)

**Strengths of the Method**:
- No additional parameters at inference — dynamic algorithm is parameter-free
- Recovery method agnostic — works with any imputation approach
- Addresses both low-fidelity and semantically misaligned reconstructions
- Theoretically motivated via information-theoretic analysis

**Weaknesses of the Method**:
- Inference cost scales with number of missing modalities (multiple forward passes per iteration)
- ICS calibration sometimes hurts on medical datasets (CAD, Infarction) where recovered modalities are consistently useful — calibration makes selection too conservative
- Gaussian parameter precomputation requires all $2^M - 1$ subsets — exponential in modality count, limiting scalability beyond ~10 modalities
- Currently limited to classification tasks (though paper discusses extensions to segmentation/detection)
